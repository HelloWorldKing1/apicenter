## 1. 统一内部模型（UnifiedModel）

链内唯一数据载体，格式无关（JSON/XML 进出，内部一律树形中间表示）。节点结构：

```
UNode
├─ kind：OBJECT | ARRAY | SCALAR
├─ OBJECT：fields: LinkedHashMap<String, UNode>（保序）+ attributes: Map<String,String>（仅 XML 适配器使用，默认空）
├─ ARRAY：items: List<UNode>
└─ SCALAR：type: STRING | INT | DECIMAL | BOOLEAN | NULL + value（原始值）
```

- **保序**：OBJECT 用 LinkedHashMap，保证 JSON 透传与 XML 渲染的顺序稳定。
- **类型标注**：JSON 解码时 number 整数 → INT（超出 long 范围 → DECIMAL）、小数 → DECIMAL；XML 全文本，解码后按 `interface_param.type` 提示转换（STRING 默认）。
- **路径工具**：`get(path)` / `set(path)` / `remove(path)`，点号路径语法见《M0-02动态映射语义规范.md》§2。
- `attributes` 仅在 `attrVsElement=ATTRIBUTE` 的 XML 编解码中填充/消费；JSON 场景恒为空。OBJECT 与 ARRAY 可互相嵌套，深度不限（引擎不设深度上限，防护交给报文大小限制，见 M0-03 §1）。

## 2. Adapter 统一契约

```java
public interface Adapter {
    AdapterType type();                     // AUTH / PROTOCOL / MESSAGE
    int order();                            // 同阶段多实例时的排序（当前每阶段至多 1 个，保留扩展）
    boolean supports(AdapterContext ctx);   // 按 ctx.phase() + 配置判断是否参与该阶段
    AdapterContext process(AdapterContext ctx); // 统一执行入口
}
```

**定稿 D1（统一入口 + phase 分流）**：链引擎只认 `phase` + `process(ctx)`，不感知适配器内部细节。协议适配器内部按 `ctx.phase()` 分流——DECODE 阶段执行 `decode(bytes, format)`、ENCODE 阶段执行 `encode(model, format)`；鉴权适配器分流——INBOUND_AUTH 阶段执行 `authenticate(...)`（结果写 `ctx.inboundAuth()`）、OUTBOUND_AUTH 阶段执行 `applyCredential(...)`（凭证写 `ctx.outbound()`）。报文适配器的 `process` 即主方法。这样新增适配器/阶段只读写上下文，不破坏契约（呼应设计 §5.2「新增适配器只读写上下文」）。

- `supports(ctx)` 默认恒 true；实现可声明仅参与特定 phase。
- 适配器**无状态、配置驱动、全局单例复用**；配置（`adapter.params`）在实例化时构建为不可变配置对象。
- 适配器抛错统一包装为 `AdapterException(errorCode, message)`（错误码见 §6）。

## 3. 链上下文（AdapterContext）

```java
public record AdapterContext(
    ChainPhase phase,               // 当前阶段（六阶段枚举，见 §4）
    UnifiedModel payload,           // 统一内部模型（链内唯一数据载体）
    InterfaceMeta iface,            // 接口标识 code / ifType / protocolIn / protocolOut / timeoutMs / maxRetries
    AppMeta app,                    // appId / name / baseUrl
    TraceMeta trace,                // traceId（span 名由阶段派生）
    AuthResult inboundAuth,         // 入站鉴权结果（appId / 是否通过 / 失败码）
    OutboundRequestSpec outbound,   // 出站请求规格（协议编码填 body，出站鉴权加凭证头，见 M0-03）
    Warnings warnings,              // 各适配器可追加的告警收集（不阻断执行）
    Map<String, Object> attrs       // 扩展位（预留）
)
```

- **可变性定稿 D2**：`payload` 与 `outbound` 允许原地修改（单请求单线程、链内顺序执行），其余字段只读；禁止为追求不可变而每阶段拷贝 payload。
- `OutboundRequestSpec` 定义见《M0-03通用客户端与对账协议.md》§2，此处仅约定其为链上下文的一部分。

## 4. 链编排（固定六阶段）

| # | 阶段（ChainPhase） | Flow A 出站 | Flow B 入站 |
|---|---|---|---|
| 1 | INBOUND_AUTH | 平台统一调用方鉴权（范围外，链引擎放 Noop 占位，预留扩展点） | 回调验签适配器（CALLBACK_AUTH 角色） |
| 2 | DECODE | protocol_in 推导（JsonProtocolAdapter / XmlProtocolAdapter） | 同左 |
| 3 | MESSAGE | 报文适配器（MESSAGE 角色） | 同左 |
| 4 | MAPPING | **固定步骤，非适配器**：映射引擎读 `interface_field_mapping[]` 执行（见 M0-02） | 同左 |
| 5 | ENCODE | protocol_out 推导 | 同左 |
| 6 | OUTBOUND_AUTH | 供应商签名适配器（AUTH 角色） | 向回调地址签名（默认 Noop） |

- **定稿 D3**：MAPPING 是链上固定步骤而非适配器——不查 `adapter` 表、不参与绑定，由映射引擎直接消费接口级 `fieldMappings[]`（呼应设计 §5.1）。
- 链模板固定，不可动态增删阶段；`order()` 仅在同阶段多实例时排序（当前每阶段至多 1 个实例，保留扩展位）。
- 链实例按 `(interface_id, if_type)` 组装一次并缓存（见 §7）。

## 5. 绑定解析（继承 / 覆盖 / 自动推导）

### 5.1 角色解析顺序表（先命中即用）

| 角色 | 解析顺序 | 最终兜底 |
|---|---|---|
| MESSAGE 报文 | ① 接口绑定 `role=MESSAGE` 且 `adapter_id` 非空 → ② 接口绑定存在但 `adapter_id=NULL`（= 显式继承）→ ③ `app.default_message_adapter_id` | 平台默认 NoopMessageAdapter（直通） |
| AUTH 供应商签名（仅 OUTBOUND 生效） | ① 接口绑定 `role=AUTH` 且非空 → ② `app.auth_adapter_id` | NoopAuthAdapter（无鉴权） |
| CALLBACK_AUTH 回调验签（仅 INBOUND 生效） | ① 接口绑定 `role=CALLBACK_AUTH` 且非空 → ② `app.callback_auth_adapter_id` | NoopAuthAdapter（无验签） |
| PROTOCOL_IN / PROTOCOL_OUT | **不参与绑定**：`interface.protocol_in/out` → 平台内置注册表自动推导实现 | 注册表仅 JsonProtocolAdapter / XmlProtocolAdapter 两个实现 |

**定稿 D4（平台默认兜底）**：默认报文适配器 = NoopMessageAdapter（透传，成败判断回退 HTTP 状态码，信封解析留给显式绑定 EnvelopeMessageAdapter 的接口）；默认鉴权 = NoopAuthAdapter。管理面提示：生产 INBOUND 接口建议显式绑定回调验签（建议级，不强制）。

**定稿 D5（协议参数承载缺口）**：协议适配器参数（JSON namingStrategy / dateFormat / nullHandling / numberPrecision；XML rootElement / namespace / attrVsElement）在设计 §5.8 有元数据定义，但表结构无承载列（`interface` 表无协议参数字段，且设计明确「协议适配器不参与绑定」）。**首期协议适配器一律使用平台默认参数**：
- JSON：保留字段名原样（不做命名转换）、ISO 日期、忽略未知字段、空值包含、整数 INT / 小数 DECIMAL；
- XML：无命名空间、元素映射（attrVsElement=ELEMENT）、根元素为约定名。

v1.1 扩展点：`interface` 表新增 `protocol_in_params` / `protocol_out_params` JSON 列。**此定稿需评审确认。**

### 5.2 灰度（binding.version）

- `interface_adapter_binding.version` 非空 → 按 `adapter(impl, version)` 精确匹配取定义。
- 为空 → 取该 impl 当前启用定义。**管理面约束 D6**：同一 impl 至多一条 `enabled=1` 的记录（多版本并存时旧版本置停用），由管理面校验保证。
- 绑定解析结果（适配器 id + 版本 + params）落链实例，执行期不再查表。

### 5.3 非法绑定忽略

类型互斥：OUTBOUND 接口上的 `role=CALLBACK_AUTH` 绑定、INBOUND 接口上的 `role=AUTH` 绑定为非法配置——链引擎解析时**忽略并追加 warning**（不阻断执行），管理面保存时给出校验提示（M1 测试点已有）。

## 6. 链异常处理与状态机边界

**定稿 D7（不污染状态机）**：只有进入出站调用（写 `outbound_request`）或送达（写 `inbound_delivery`）才落运行表；链上失败直接返回统一错误信封 + 记 `call_log`。

| 阶段失败 | 错误码 | 运行表 |
|---|---|---|
| INBOUND_AUTH 失败（验签失败 / 时间戳过期） | 40100 / 40101 | 不落（Flow B 不落 `inbound_delivery`，与 M3 测试点一致） |
| DECODE 失败（报文格式非法） | 40002 | 不落 |
| MAPPING 失败（nullStrategy=ERROR 字段缺失 / 规则求值异常） | 40001 / 50000 | 不落 |
| ENCODE 失败 | 50000 | 不落 |
| MESSAGE 适配失败 | 50000 | 不落 |

- 链失败后 `outbound_request` 无记录；诊断依赖 `call_log`（traceId 关联）与告警收集。
- 出站诊断字段：`outbound_request.out_payload` 即映射后出站报文（可行性风险应对「映射结果落 mapped_payload 供诊断」，复用 out_payload 列，不另设列）。

## 7. 链缓存与失效

- 链组装缓存 key = `interface_id`（含绑定解析结果与适配器配置快照）。
- 失效事件（管理面变更时发出）：接口发布 / 版本变更 / 快照回滚、绑定增删改、适配器启停 / 参数变更、应用默认适配器变更。
- 兜底：缓存 TTL 5 分钟（事件失效为主，TTL 防漏发）。

## 8. 适配器注册表（首期实现清单）

impl 字符串 → Spring Bean（按 impl 名注册）。首期范围与《可行性报告》§7 建议一致：

| 类型 | 首期实现（M2） | 后续批次 |
|---|---|---|
| auth | NoopAuthAdapter、ApiKeyAuthAdapter、HmacAuthAdapter（复用旧版 SignatureService 经验）、BearerTokenAuthAdapter、CloudSignatureAdapter（scheme=TC3/AWS4/ACS3 子实现）、CloudCallbackSignatureAdapter | OAuth2×2、Basic、mTLS（二、三批） |
| protocol | JsonProtocolAdapter、XmlProtocolAdapter | — |
| message | NoopMessageAdapter、EnvelopeMessageAdapter、HeaderMappingAdapter | — |

每个 impl 声明参数 schema（原型 ADAPTER_FIELDS 模式），实例化时按 schema 校验 `adapter.params`；凭证类参数不落 `adapter.params`，统一存 `app_credential` 表（见 M0-04 凭证轮换存储方案）。

## 9. 定稿决策记录（ADR）

| # | 决策 | 备选 | 理由 |
|---|---|---|---|
| D1 | 统一入口 process(ctx) + phase 分流 | 引擎直接调 decode/encode/authenticate/applyCredential 专用方法 | 链引擎只认阶段，新增适配器不改引擎；专用语义保留在基适配器内 |
| D2 | payload/outbound 原地修改，其余只读 | 每阶段拷贝不可变上下文 | 单请求单线程顺序执行，拷贝纯开销 |
| D3 | MAPPING 为固定步骤非适配器 | 映射引擎做成适配器实例 | 设计 §5.1 已定「字段映射为接口级配置，链上固定步骤」 |
| D4 | 平台默认 = NoopMessageAdapter（直通）+ NoopAuthAdapter | 默认绑 EnvelopeMessageAdapter | 不配置即不转换，信封解析仅对显式绑定的接口生效，避免隐式行为 |
| D5 | 首期协议参数用平台默认，不支持 per-interface 定制 | 扩展 binding 角色 | 设计禁止协议适配器参与绑定；表结构无承载列；v1.1 加列最干净 |
| D6 | 同 impl 至多一条 enabled=1 | 按版本号排序取最新 | 版本号为字符串，排序语义不可靠；管理面约束简单可校验 |
| D7 | 链失败不落运行表 | 落 INIT 态再流转 | 设计 §5.4「解析失败不污染状态机」 |
