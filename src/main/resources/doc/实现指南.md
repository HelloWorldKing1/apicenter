## 1. 总体架构与代码地图

所有源码在 `src/main/java/com/deepx/apicenter/` 下：

| 包 | 类 | 职责 |
|---|---|---|
| `controller/` | `OrderController`、`CallbackController` | HTTP 入口：ERP 推单、第三方回调；验签后转发 Service |
| `service/` | `OrderSyncService`、`PartnerInvoker`、`CallbackDeliveryService`、`SignatureService` | 编排：出站推单、调用第三方、入站送达、签名验签 |
| `mapper/` | `OrderMapper` | MapStruct 编译期映射：`OrderDto ⇄ PARTNER_A JSON / PARTNER_B XML` |
| `client/` | `PartnerAClient`、`PartnerBClient`、`ErpCallbackClient` | `@HttpExchange` 声明式 HTTP 客户端（JSON / XML / ERP 送达） |
| `dto/` | `OrderDto`、`PartnerAOrderRequest`、`PartnerBOrderRequest`、`PartnerResponse`、`ErpOrderResponse`、`OrderStatusCallbackDto` | 统一模型 + 各渠道 DTO（含 Jackson 注解） |
| `config/` | `ChannelProperties`、`RestClientConfig` | 渠道配置绑定；RestClient 与客户端代理装配 |
| `aspect/` | `LoggingAspect` | AOP 统一请求日志 + 敏感脱敏 |
| `worker/` | `CompensationWorker`、`IncrementalSyncJob` | 定时补偿重放；定时增量拉取 |

**Flow A 出站请求流转**：

```
OrderController.pushOrder        controller/OrderController.java       验签 → 调 Service
   └─ OrderSyncService.pushOrder  service/OrderSyncService.java        落库 INIT→MAPPING → 调 PartnerInvoker
        └─ PartnerInvoker.invoke  service/PartnerInvoker.java          @Retryable：映射 + 调用客户端
             ├─ OrderMapper.toPartnerA   mapper/OrderMapper.java       字段映射（含金额/时间/嵌套）
             └─ PartnerAClient.pushOrder client/PartnerAClient.java    @HttpExchange 调第三方
```

## 2. Flow A 出站：如何调用第三方接口

### 2.1 入口与编排

- **`controller/OrderController.java`** `pushOrder()`：接收 ERP 的 `POST /api/orders`，先 `signatureService.verify(...)` 验签（§8），通过后调 `orderSyncService.pushOrder(order)`。
- **`service/OrderSyncService.java`** `pushOrder()` 编排：
  1. `insertRequest(order, INIT)` 落库（outbox 语义，先记后发，供补偿用）；
  2. `updateStatus(requestId, MAPPING)`；
  3. `partnerInvoker.invoke(order)` —— 真正发起对第三方的调用；
  4. 成功 → `updateStatus(SUCCESS)` + `insertCallLog` + `ErpOrderResponse.success(...)` 返回。

### 2.2 真正"调用第三方"的地方

- **`service/PartnerInvoker.java`** `invoke(OrderDto order)`：
  ```java
  @Retryable(includes = {HttpServerErrorException.class, TooManyRequests.class, ResourceAccessException.class},
             maxRetries = 4, delay = 200, multiplier = 2, maxDelay = 2000, timeUnit = TimeUnit.MILLISECONDS)
  public PartnerResponse invoke(OrderDto order) {
      PartnerAOrderRequest request = orderMapper.toPartnerA(order); // 先映射
      return partnerAClient.pushOrder(request);                     // 再调用
  }
  ```
  > **为什么独立成一个 Bean**：`@Retryable` 底层是 AOP 代理，若方法在 `OrderSyncService` 内自调用，代理不生效。抽成 `PartnerInvoker` 后由外部注入调用，重试切面才能拦截。

- **声明式客户端 `client/PartnerAClient.java`**（PartnerBClient 同构，XML）：
  ```java
  @HttpExchange
  public interface PartnerAClient {
      @PostExchange(value = "/v1/order/push", contentType = "application/json")
      PartnerResponse pushOrder(@RequestBody PartnerAOrderRequest request);
  }
  ```
  组件不写 HTTP 模板代码，由 Spring 在**`config/RestClientConfig.java`** 里生成代理。

### 2.3 客户端装配

- **`config/RestClientConfig.java`** `createClient(...)`：
  ```java
  RestClient restClient = RestClient.builder()                       // Boot 4.1 不自动配 Builder，用静态工厂
          .baseUrl(ch.getBaseUrl())                                   // 渠道地址 :8101
          .defaultHeaders(h -> h.setBearerAuth(ch.getAuthToken()))    // 鉴权头
          .requestFactory(factory)                                    // 读超时 3000ms
          .build();
  return HttpServiceProxyFactory.builderFor(RestClientAdapter.create(restClient))
          .build().createClient(clientType);                          // 生成 @HttpExchange 代理 Bean
  ```
  默认转换器按 classpath 自动探测：Jackson 3 JSON + XML（`jackson-dataformat-xml`）。traceparent 由 OpenTelemetry 自动注入，无需手写。

## 3. 字段映射（出站 + 返回值映射）

### 3.1 出站映射：`mapper/OrderMapper.java`

```java
@Mapper(componentModel = "spring")
public interface OrderMapper {
    @Mapping(source = "totalAmount", target = "totalAmountCent", qualifiedByName = "yuanToCent")  // 元→分
    @Mapping(source = "createdTime", target = "createdAt", dateFormat = "yyyy-MM-dd'T'HH:mm:ss")   // 时间格式
    @Mapping(source = "buyerName",   target = "buyer.name")                                        // 平铺→嵌套
    @Mapping(source = "buyerPhone",  target = "buyer.mobile")
    @Mapping(source = "shippingAddress", target = "receiver")                                      // 重命名
    @Mapping(source = "remark",      target = "note")
    PartnerAOrderRequest toPartnerA(OrderDto dto);

    @Mapping(source = "orderStatus", target = "status", qualifiedByName = "statusToInt")           // NEW→1/PAID→2/...
    @Mapping(source = "totalAmount", target = "totalAmount", qualifiedByName = "yuanToCent")
    @Mapping(source = "createdTime", target = "createdTime", dateFormat = "yyyyMMddHHmmss")
    PartnerBOrderRequest toPartnerB(OrderDto dto);
}
```
- **金额**：`@Named("yuanToCent")` 默认方法 `BigDecimal ×100 → long`；
- **状态**：`@Named("statusToInt")` `NEW→1/PAID→2/SHIPPED→3`；
- **时间**：`dateFormat`（`toPartnerA` 输出 ISO-8601，`toPartnerB` 输出 `yyyyMMddHHmmss`）；
- **嵌套/列表**：`buyer.name` 聚合、明细 `items` 递归调用 `toItemA/toItemB`（MapStruct 编译期生成 `OrderMapperImpl`）。

### 3.2 DTO 上的 Jackson 注解

- `dto/PartnerAOrderRequest.java`：`@JsonProperty("orderNo")` 等显式固定 JSON 键名；
- `dto/PartnerBOrderRequest.java`：`@JacksonXmlRootElement("OrderPushRequest")` / `@JacksonXmlProperty` / `@JacksonXmlElementWrapper(useWrapping=false)`（Jackson 3 注解包为 `tools.jackson.dataformat.xml.annotation.*`）。

### 3.3 返回值映射

第三方返回统一折叠为 **`dto/PartnerResponse.java`**（`code/message/orderNo/status`），再在 `service/OrderSyncService.java` `pushOrder` 中组装成 ERP 响应：
```java
return ErpOrderResponse.success(resp.orderNo(), resp.status(), order.totalAmount());
```
（`ErpOrderResponse.success(...)` 静态工厂在 `dto/ErpOrderResponse.java`，金额分→元由原始 `totalAmount` 回显，`code=0`、`success=true`。）

## 4. 失败重试

### 4.1 短重试：`service/PartnerInvoker.java`

`@Retryable`（Spring 7 原生 `org.springframework.resilience.annotation`，扁平参数）：
- `includes`：5xx / 429 / IO&读超时（`HttpServerErrorException` / `HttpClientErrorException.TooManyRequests` / `ResourceAccessException`）
- `maxRetries = 4`：总尝试 5 次（对齐 `max-attempts=5`）
- 指数退避：`delay=200ms ×2`，上限 `maxDelay=2000ms` → 200/400/800/1600ms

### 4.2 重试耗尽后的分支：`service/OrderSyncService.java` `pushOrder`

```java
try {
    PartnerResponse resp = partnerInvoker.invoke(order);     // @Retryable 内部重试
    updateStatus(requestId, SUCCESS);
    return ErpOrderResponse.success(...);
} catch (HttpClientErrorException e) {                        // 400 等业务错误
    long deadLetterId = insertDeadLetter(requestId, order, e);// 写 dead_letter 表
    updateStatus(requestId, DEAD_LETTER);                     // 不重试
    return ErpOrderResponse.failure(...);
} catch (ResourceAccessException e) {                         // 读超时/连接异常（重试耗尽后）
    updateStatus(requestId, UNKNOWN);
    return reconcile(requestId, order);                       // 对账
}
```

### 4.3 持久化补偿：`worker/CompensationWorker.java`

```java
@Scheduled(fixedDelayString = "${app.integration.retry-worker-fixed-delay-ms}")   // 3000ms
public void compensate() {
    // 出站：integration_request.status=COMPENSATING 的重放
    // 入站：callback_delivery.delivery_status=PENDING 的重发
}
```
状态机载体为 `service/OrderSyncService.java` 内嵌枚举 `RequestStatus`：
`INIT → MAPPING → SENDING →(500/429→RETRYING↺)→ COMPENSATING → SUCCESS`；`4xx→DEAD_LETTER`；`超时→UNKNOWN→对账`。

## 5. 请求日志的读写

### 5.1 写日志：`aspect/LoggingAspect.java`

`@Around("execution(* com.deepx.apicenter.service..*(..))")` 拦截所有 Service 方法：
- 记录方法签名、入参（脱敏后）、出参、耗时、异常；
- 脱敏：手机号 `138****1234`、`authorization/secret/token` 值打码。

### 5.2 落库：`service/OrderSyncService.java` `insertCallLog(...)`

向 `integration_call_log` 写一行（`trace_id/span_id/direction/channel/url/method/status_code/latency_ms/req_headers(脱敏)/req_body/resp_body`）。

### 5.3 读 / 链路追踪

- traceId 由 OpenTelemetry 自动注入日志（logback 可配 `%traceId`），一次调用从 ERP → 组件 → 第三方同 traceId；
- `config/RestClientConfig.java` 的 RestClient 自动透传 W3C `traceparent`，出站调用不丢链。

## 7. Flow B 入站回调：配置、调用、返回值映射

### 7.1 配置（ERP 预配置订阅）

- 落表 `callback_subscription`（`src/main/resources/schema.sql`）：`channel_code / callback_path / erp_callback_url / erp_auth_token / erp_signature_secret`；
- 示例配置见 `api演示 demo.html` Flow B Tab：
  ```
  channelCode=PARTNER_A, callbackPath=/callback/PARTNER_A/order-status,
  erpCallbackUrl=http://localhost:8103/api/erp/order-status, erpAuthToken=erp-token
  ```

### 7.2 调用入口与验签：`controller/CallbackController.java`

```java
@PostMapping("/{channel}/order-status")
public ... orderStatus(@PathVariable String channel,
                       @RequestHeader("X-Partner-Signature") String signature,
                       @RequestHeader("X-Timestamp") String timestamp,
                       @RequestBody OrderStatusCallbackDto event) {
    ChannelProperties.Channel ch = channelProperties.getChannels().get(channel); // 按渠道取密钥
    if (!signatureService.verify(signature, timestamp + event.orderNo(), ch.getSignatureSecret(), ...)) {
        return 401;                                   // 验签失败 → DROPPED
    }
    return ok(callbackDeliveryService.handleCallback(channel, event)); // 处理并回 ack
}
```

### 7.3 映射与送达：`service/CallbackDeliveryService.java` `handleCallback`

1. 渠道回调 DTO → ERP 事件 DTO：`new OrderStatusCallbackDto(event.event(), event.orderNo(), event.status(), channel)`（`source` 标记来源渠道）；
2. 落 `callback_delivery(RECEIVED)`；
3. `erpCallbackClient.deliver(erpEvent)`（`client/ErpCallbackClient.java`，`@PostExchange` 2xx 即 ack）→ 置 `ERP_ACKED`；
4. 送达失败 → 置 `PENDING`，交补偿 worker 重发（`worker/CompensationWorker.java`）。

### 7.4 返回值映射（回给第三方）

```java
return ResponseEntity.ok(Map.of("code", 0, "msg", ack));   // 统一 ack：{code:0, msg:"ok"}
```
ERP 侧收到的回调体即 `OrderStatusCallbackDto` 的 `orderId/status/source` 字段。

## 8. 签名与验签

- **`service/SignatureService.java`**：`sign(canonicalString, secret)` 计算 HMAC-SHA256 十六进制；`verify(...)` 先校验时间戳容差（`signature-tolerance-seconds=300`）再做恒定时间比对。
- **Flow A（ERP → 组件）**：`controller/OrderController.java`，canonical = `appId + timestamp + orderId`，密钥 = ERP 渠道 `erp-secret`；
- **Flow B（第三方 → 组件）**：`controller/CallbackController.java`，canonical = `timestamp + orderNo`，密钥 = 该渠道 `secret-a` / `secret-b`。

## 10. 已知简化与遗留项（示例级，非本期实现）

以下为本示例代码相对设计文档**有意简化 / 未接通**的部分，生产实现时需补齐：

### 逻辑缺口

1. **5xx 重试耗尽未转 COMPENSATING**：`OrderSyncService.pushOrder` 未捕获 `HttpServerErrorException`，重试耗尽后状态停在 `MAPPING`、向 ERP 返回 500。
2. **`COMPENSATING` 状态从未被设置**：全代码无 `updateStatus(COMPENSATING)`，`CompensationWorker` 出站扫描恒空，补偿链路为占位。
3. **PARTNER_B（XML）渠道未被路由调用**：`PartnerInvoker.invoke` 只走 `toPartnerA`，`toPartnerB` / `PartnerBClient` 为演示死代码，无渠道路由。
4. **管理端点缺失**：`GET /api/integration/requests/{id}`、`GET /api/integration/dead-letters`、`POST/PUT /api/subscriptions` 未实现。
5. **回调订阅未真正生效**：`callback_subscription` 表未读，送达 URL 硬编码为 `/api/erp/order-status`，`subscription_id=1` 固定。
6. **`integration_channel` 表未使用**：无种子数据，渠道配置仅读 application.yaml。

### 与设计的行为差异

7. **读超时会被重试**：`@Retryable` includes 含 `ResourceAccessException`，读超时先重试 5 次再进 UNKNOWN（设计 §6.3 注释倾向直接 UNKNOWN）。
8. **`reconcile` 一律置 SUCCESS**：设计 §6.5 为 SUCCESS / DEAD_LETTER / COMPENSATING 三态，代码简化为一律 SUCCESS。

### 健壮性与文案

9. **未知渠道回调 NPE**：`CallbackController` 的 `{channel}` 不在配置时 `ch` 为 null → NPE → 500，应返回 400/404。
10. **文案残留**：`实现指南.md:201`「见 design.md §8」、demo 页 footer「设计文档 design.md」等旧名残留。

### 已核对一致

- schema.sql 9 表与代码 insert/update 列完全匹配；`@Retryable` 退避（200/400/800/1600）与 demo 一致；签名 canonical 规则前后端一致；dateFormat 已修（无 OffsetSeconds）。
