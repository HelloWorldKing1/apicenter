# 管理面账号登录设计方案（v1.0 · 2026-09-18）

> **定位**：把此前明确推迟的「B 类 P0 —— 管理面无鉴权」补上，**只做认证**（登录 / 注册 / 退出 / 改密），
> **不做权限**（无角色、无资源授权）。范围严格限定在管理面 REST（`/api/admin/**`）。
>
> **不涉及**平台对外接口路径（`/{platformPath}`，出站调用与入站回调）—— 那是「调用方鉴权」，
> 属另一特性（《API中心设计方案.md》§1.2 / §5.3），本方案**一行都没动**它。
>
> 落地状态：**已落地**（2026-09-18）。表 `admin_user` / `admin_session`（第 21、22 张）已应用到开发库；
> 认证后端 19 例 + **账号管理 29 例 + 角色（RBAC 第一层）14 例**；前端 24 单测 / 2 SSR 用例；接口与错误码见 §4、账号管理见 §13、角色见 §14。

## 1. 目标与非目标

| | 内容 |
|---|---|
| **目标** | ① 账号登录（不透明 Bearer 令牌）② 注册（含「首个账号」首次初始化）③ 退出（即时失效）④ 修改密码（吊销其他会话）⑤ 未登录访问管理面被拦（HTTP 401 + 统一信封）⑥ **账号管理**（列表 / 新建 / 启停用 / 重置口令 / 解锁 / 删除，含「不把系统锁死」守卫，见 §13）|
| **非目标** | 细粒度资源授权（本方案只有 3 个角色，见 §14）、找回密码（邮件）、SSO/OAuth、多租户、操作审计表（变更只落 `log.info/warn`）、令牌滚动刷新 |

## 2. 决策记录（D-AUTH-*）

| # | 决策 | 理由 / 备选 |
|---|---|---|
| D-AUTH-1 | **不透明 Bearer 令牌**（DB `admin_session`，只存 SHA-256 摘要） | 备选 ①Cookie Session：引入 CSRF 面、跨域/代理联调更绕；备选 ②JWT：需引依赖且**无法即时吊销**。令牌方案还能直接 `curl -H 'Authorization: Bearer …'` 复现问题 |
| D-AUTH-2 | 口令 **PBKDF2-HMAC-SHA256**（JDK 自带，120k 迭代，每用户随机盐，格式自描述 `pbkdf2$iter$salt$hash`） | 零新增依赖；与 `CryptoService`（可逆 AES，凭证签名要重算明文）刻意分开：口令必须**不可逆** |
| D-AUTH-3 | 保护范围 = `/api/admin/**` | 平台对外路径不动（调用方鉴权是另一特性）；静态资源与 `/actuator/health` 放行 |
| D-AUTH-4 | 令牌 TTL 12h + **惰性续期**（距上次续期 > 1h 才写一次） | 避免「每请求一次 UPDATE」的写放大；`renewIfDue` 把判据放进 SQL（一条语句，不是读+写两次往返） |
| D-AUTH-5 | 登出**删行**、改密**吊销该账号其他会话**（当前会话保留） | 即时失效不依赖 TTL；改密后自己不被踢出 |
| D-AUTH-6 | 开放注册（`allow-register` 默认 true），但**系统无任何账号时永远允许** | 用户明确要注册功能；「首个账号」规则避免把管理员锁在门外。生产建议建号后置 false（§6.4） |
| D-AUTH-7 | 暴力破解：连续失败 5 次 → 锁定 5 分钟（成功登录清零，锁定期内**密码正确也拒**） | 计数落库（多实例同口径）；锁定不影响其他账号 |
| D-AUTH-8 | 登录失败**不区分**「用户不存在 / 密码错」，文案统一 | 防账号枚举；但会给出「还可尝试 N 次」（内部工具，可观测性优先于极致隐匿） |
| D-AUTH-9 | 开关 `auth.enabled`（默认 true）；集成测试里直连管理面 HTTP 的类统一置 false | 既保留既有用例语义，又让 `AuthIntegrationTest` 用默认值证明「过滤器真的生效」 |
| D-AUTH-10 | **`login()` 刻意不加 `@Transactional`** | 见 §10 坑 1：加了会把「失败计数」一起回滚，锁定形同虚设 |

## 3. 数据模型（第 21 / 22 张表）

```sql
admin_user(id, username UNIQUE, display_name, password_hash, status, failed_attempts,
           locked_until, last_login_at, password_updated_at, created_at, updated_at)
admin_session(id, user_id, token_hash UNIQUE, client_info, created_at, last_seen_at,
              renewed_at, expires_at)
```

- 命名规则：`username` 3-32 位小写字母/数字/`_` `.` `-`，**统一小写存储**（避免大小写混淆）；口令 8-64 位且**同时含字母与数字**。
- `admin_session` 只存**摘要**：库泄露 ≠ 可登录（与 M0-04「凭证不落明文」同一纪律）；`client_info` 记 IP + UA 摘要（诊断），截断 200 字符。
- 无外键（全库一致），`user_id` / `expires_at` 建索引；过期会话由**登录时机会式清理**（不为一张几乎不增长的表引入调度任务）。
- 删除策略：删账号 → 联删其会话（`schema.sql` 删除约定已登记）。

## 4. 接口清单（`/api/admin/auth/*`）

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/status` | **豁免** | 登录页引导：`{enabled, hasUser, allowRegister}`（`hasUser=false` → 首次初始化，登录页默认切到「注册」） |
| POST | `/login` | **豁免** | `{username, password}` → `{token, expiresAt, user}` |
| POST | `/register` | **豁免** | `{username, password, displayName?}` → 同上（**注册即登录**，少一步） |
| GET | `/me` | 需登录 | 当前账号 `{id, username, displayName, lastLoginAt}` |
| POST | `/password` | 需登录 | `{oldPassword, newPassword}` → 校验原密码 → 更新 → **吊销其他会话** |
| POST | `/logout` | 需登录 | 删除当前令牌行（即时失效） |

账号管理端点（v1，2026-09-18 落地）见 **§13**：`GET/POST /api/admin/users`、`PUT /{id}`、`POST /{id}/password`、`POST /{id}/unlock`、`DELETE /{id}`，错误码新增 `40405` 账号不存在。

**错误码**（新增；`40100/40101` 已被入站回调验签占用，故从 40104 起）：

| 码 | HTTP | 含义 |
|---|---|---|
| 40104 | 401 | 未登录 / 令牌缺失·无效·过期 |
| 40105 | 401 | 用户名或密码错误 / 原密码不正确 |
| 40106 | 401 | 账号已锁定（含剩余分钟数） |
| 40301 | 403 | 注册已关闭 |
| 40901 | 409 | 用户名已存在 |
| 40001 | 400 | 用户名或口令不符合规则（长度/字符集/字母数字混合）；账号管理的守卫拒绝（最后账号 / 动自己） |
| 40405 | 404 | 账号不存在（账号管理） |

## 5. 守卫（后端过滤器 + 前端路由守卫）

**后端 `AdminAuthFilter`**（`OncePerRequestFilter`，`@Order(HIGHEST_PRECEDENCE + 10)`）：

```
非 auth.enabled            → 放行
非 /api/admin 前缀         → 放行（对外接口路径 /actuator/health/静态资源）
/auth/{login,register,status} → 放行（登录页自身要能访问）
OPTIONS（CORS 预检）        → 放行  ← 2026-09-18 CORS 事故同类坑：拦掉会让浏览器所有写操作失败
无 Authorization: Bearer    → 401 + {code:40104}
令牌无效/过期               → 401 + {code:40104}
通过                        → 请求属性注入账号 + 令牌摘要（Controller 直接取用）
```

**前端**：

- `api/http.js`：请求自动带 `Authorization`；响应 `401`/`40104` 且**非** `/auth/*` 端点 → 清登录态 + 整页跳 `/login?redirect=<原路径>`（整页跳转而非 router，避免 http ↔ router 循环依赖）；
- `router/index.js`：已登录访问 `/login` → 回概览；未登录访问业务页 → 带 `redirect` 跳登录页；`auth.enabled=false` 时放行（前后端口径一致）；
- `utils/auth.mjs`：令牌/用户存取（storage 可注入，便于单测；**SSR 能力守卫**）、表单预校验（与后端同规则）、`redirectTarget` 只接受站内相对路径（**防开放重定向**）。

## 6. 安全口径

1. **口令**：不可逆摘要（PBKDF2 120k + 随机盐 + 常量时间比较）；任何接口、日志、错误信息都不回显口令；库里存的是 `pbkdf2$…`。
2. **令牌**：32 字节 `SecureRandom` → Base64URL；库内只有 SHA-256 摘要；明文只在登录/注册响应出现一次。
3. **会话生命周期**：TTL 12h（惰性续期，最长有效期内可持续使用）；登出 / 改密 / 过期即失效；`admin_session` 过期行机会式清理。
4. **注册风险与关闭方式**：默认开放（用户要求）。生产建议：`app.api-center.auth.allow-register: false`（首个账号仍可注册，之后新增账号由 DBA 或后续「账号管理」能力承担）。
5. **未做的加固（诚实登记）**：无 IP 维度限流（只有账号维度锁定）、无 MFA、无密码历史、无登录审计表（仅 `log.info/warn`：成功/失败/锁定/改密）、令牌不可滚动刷新（到期需重登）。

## 10. 落地踩坑（真坑，务必别踩回）

1. **`login()` 加 `@Transactional` = 失败计数被回滚**（实测）：登录失败要抛 `BizException`，同一事务里先前写的
   `failed_attempts + 1` 会一起回滚 → 连续失败次数永远是 1，**锁定形同虚设**（`连续失败达阈值_锁定且正确密码也被拒` 用例抓到）。
   结论：这种「写入 + 抛异常」的流程**不要挂事务**，或让计数写走 `REQUIRES_NEW`。
2. **CORS 预检必须放行**：`OPTIONS /api/admin/**` 不带 `Authorization`，过滤器拦掉会让浏览器**所有写操作**失败
   （与 2026-09-18 的 CORS 单 Origin 事故同一类症状：请求根本不进引擎、无 call_log）。
3. **Frontend 单测/SSR 的能力守卫**：`utils/auth.mjs` 顶层访问 `localStorage` 必须做 `typeof` 守卫，否则 SSR 冒烟直接抛；
   冒烟的 `ElStub` 未声明 `props` ⇒ 表单标签（`label`）落在 **attrs** 上（`attrs.label`），不是 `props.label`。
4. **开发库即测试库**：`AuthIntegrationTest` / `AdminUserIntegrationTest` 会创建真实账号 → 用例内用随机后缀 + `@AfterEach` 清理自己创建的账号与会话。
5. **两个 `long` 参数的守卫方法极易传反**（真 bug，已被单测抓到）：`guardLockout(operatorId, target, action)` 的调用处一度把 **target id** 当 operatorId 传进去 → 判成「操作自己」→ **停用他人永远被拒**。修法是逐一复核调用点，并在方法注释写明「第一个参数是操作者」（`AdminUserServiceTest#停用他人_改状态并吊销其全部会话` 就是这条的回归）。
6. **共享开发库上无法稳定复现「最后一个可用账号」**：集成测试跑在真实库上，库里是否有别的可用账号取决于环境 → 精确守卫语义交给 `AdminUserServiceTest`（Mockito 控 `countEnabled()`）钉死；集成测试只断言「一律被拒」这类环境无关的事实。

## 11. 验收速查（curl）

```bash
BASE=http://localhost:8080/api/admin

# 首次初始化（无账号时）：注册即登录
TOKEN=$(curl -s -X POST $BASE/auth/register -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"Passw0rd","displayName":"管理员"}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["data"]["token"])')

curl -s $BASE/auth/me -H "Authorization: Bearer $TOKEN"            # 当前账号
curl -s $BASE/apps                                                # 40104（未带令牌）
curl -s $BASE/apps -H "Authorization: Bearer $TOKEN" | head -c 120 # 正常
curl -s -X POST $BASE/auth/password -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"oldPassword":"Passw0rd","newPassword":"NewPassw0rd"}'     # 改密（吊销其他会话）
curl -s -X POST $BASE/auth/logout -H "Authorization: Bearer $TOKEN" # 退出
```

界面：浏览器打开管理面 → 未登录自动跳 `/login`；首次使用按提示创建账号 → 顶栏右侧可改密 / 退出。

## 13. 账号管理（v1，2026-09-18 落地）

页面：管理面侧边栏「**账号管理**」（`/users`，`views/Users.vue`）。**无权限分级**（v1 明确不做 RBAC），
因此页面顶部常驻警示，并且只实现「不把系统锁死」的两条底线。

### 13.1 端点

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/users?keyword=` | 列表（用户名/显示名模糊）；行内含 `sessionCount`（有效会话数）、`lockedUntil`、`lastLoginAt`、`createdAt`；**永不返回口令摘要** |
| POST | `/api/admin/users` | 新建账号（不自动建会话，新账号自行登录）；重名 40901 / 规则不符 40001 |
| PUT | `/api/admin/users/{id}` | 编辑：显示名 + 状态（`status` 省略 = 不变）；**停用即吊销该账号全部会话** |
| POST | `/api/admin/users/{id}/password` | 重置口令（只能重置**他人**；重置即吊销其全部会话） |
| POST | `/api/admin/users/{id}/unlock` | 解除锁定（清 `failed_attempts` 与 `locked_until`） |
| DELETE | `/api/admin/users/{id}` | 删除账号（联删会话） |

### 13.2 守卫（安全底线，服务端权威）

判定顺序固定为 **① 最后一个可用账号 → ② 自己**（单账号环境下提示更贴切）：

| 守卫 | 触发条件 | 结果 |
|---|---|---|
| ① 不把系统锁死 | 目标是 ENABLED 且 `countEnabled() <= 1` | 40001「这是最后一个可用账号，不能停用/删除…」 |
| ② 不能动自己 | `target.id == 操作者.id` | 40001「不能停用/删除当前登录的账号」；重置口令 → 引导走「修改密码」 |

> 「不能动自己」覆盖：停用、删除、重置口令（**改显示名允许**）。前端 `utils/users.mjs` 的 `accountGuard()`
> 是这两条的**客户端镜像**（按钮禁用 + 理由文案），服务端仍会再校验一次。

### 13.3 前端

## 14. 角色与权限（RBAC 第一层，2026-09-18 落地）

**只有三个角色，权限差异集中在两处**（不做资源级授权，也不做字段级裁剪）：

| 角色 | 管理面读写 | 账号管理 | 删除账号 / 变更角色 |
|---|---|---|---|
| `OWNER` 拥有者 | 全部 | 全部 | 可以 |
| `ADMIN` 管理员 | 全部 | 新建（只能建只读）/ 启停用 / 重置口令 / 解锁 / 改显示名 | 不可 |
| `VIEWER` 只读 | **只读**（GET；个人改口令 / 退出除外） | 不可（菜单与路由都不可达） | 不可 |

层级：`OWNER > ADMIN > VIEWER` —— **高等级可以管理低等级账号，反之不可**（同级也不可，避免互相停用）。

### 14.1 强制位置（只有两处，避免散落在各 Controller）

| 位置 | 规则 | 错误码 |
|---|---|---|
| `AdminAuthFilter`（端点级） | `VIEWER` 的非 GET 管理面请求（`/api/admin/auth/**` 除外） | `40302` 只读角色不能写 |
| 同上 | `/api/admin/users/**` 要求 `OWNER`/`ADMIN` | `40303` 无账号管理权限 |
| `AdminUserService`（语义级） | ADMIN 不能删账号 / 不能改角色 / 不能操作 OWNER；OWNER 不能改自己角色；不能降级或删除**最后一个 OWNER** | `40303` / `40001` |

### 14.2 数据与角色分配

- `admin_user.role VARCHAR(16) NOT NULL DEFAULT 'VIEWER'`（**最小权限默认**）；迁移把**首个账号**提升为 `OWNER`（已应用到开发库）。
- 注册：**首个账号 = OWNER**，之后注册 = `VIEWER`（开放注册不产生管理员）。
- 新建账号：弹窗选角色（ADMIN 只能选只读）；`role` 未传 = `VIEWER`。
- **角色变更会吊销该账号全部会话**（避免旧权限残留），重新登录即拿到新权限；角色每请求从库读取 → 变更即时生效。

### 14.3 前端

- `utils/roles.mjs`（与服务端 `RoleRules` 一一对应的镜像）：`canManageAccounts / canDeleteAccount / canChangeRole / canOperate / assignableRoles`。
- 路由 `meta.roles: ['OWNER','ADMIN']`（`/users`）：无权限 → 回概览并提示角色名；侧边栏菜单按角色**隐藏**「账号管理」。
- 账号管理页：新增「角色」列与角色下拉（编辑时非 OWNER 置灰并说明原因）、「删除」按钮仅 OWNER 可用、等级不足的行给出原因文案；顶栏账号区显示当前角色。
- 登录页：注册 Tab 提示「注册得到的是只读角色（VIEWER）」。

### 14.4 测试

`RoleRulesTest`（6，矩阵）、`AdminUserServiceTest`（+9 角色守卫）、`AdminUserIntegrationTest`（+4：VIEWER 只读 40302 且账号管理 40303、但可改自己口令/退出；ADMIN 可管低等级但不能删/改角色/动 OWNER；OWNER 变更角色后旧会话失效且不能改自己角色；非法角色 40001）、
前端 `utils/roles.test.mjs`（6）+ `utils/users.test.mjs`（角色维度）——共 **14 例**后端 + 6 前端。

## 15. 「记住用户名」与「记住密码」（2026-09-24 落地）

**需求**：登录页要"记住密码"，省得每次手输。**决策（需求方选②「平台本地记住口令（带风险提示）」）：提供，但按下面的方式。**

| 能力 | 做法 | 说明 |
|---|---|---|
| **记住用户名**（默认**开**） | `localStorage['apicenter.rememberUsername']` + 开关标记，只存**用户名**；取消勾选**同时清掉旧值** | 无敏感信息、收益最大；`utils/loginPrefs.mjs`（storage 可注入 + 顶层能力守卫 ⇒ SSR 安全） |
| **记住密码**（默认**关**） | **加密**保存在本机：密钥 = `crypto.subtle.generateKey(AES-GCM-256, extractable=false)` —— **不可导出**，存 **IndexedDB**；密文 = AES-GCM（随机 IV + 认证标签）也存 IndexedDB；开关标记存 `localStorage` | 勾选**前强制风险确认**（`ElMessageBox` + `REMEMBER_PASSWORD_RISK` 文案）；取消勾选 ⇒ **删密钥+密文**；**改密成功后自动清除** |
| **免重复登录** | 已有 **12h TTL + 惰性续期**（活跃用户等于滑动续期） | 因此**不提供**「记住我 N 天」长会话（只放大令牌被盗后的利用窗口；如确需，另立项并收紧续期 + 顶栏提示长期会话） |
| 与浏览器密码管理器 | 两者**并存**：浏览器管理器（`autocomplete` 已配好）仍是**推荐**方式，平台本地记忆是其兜底 | 页面明确提示二者区别 |

### 15.1 威胁模型（**必须如实告知**，页面有确认弹窗，UI 与文档措辞一致）

| 能防 | 不能防 |
|---|---|
| 离线读取浏览器 profile / 备份里的凭据（拿到的是密文） | **同源脚本（XSS）**：它能调用本模块解密出明文 |
| 只读存储的扩展 / 手工翻 `localStorage` | 已拿到本机用户会话的攻击者（能开 DevTools / 注入脚本） |
| 把密文拷到别的浏览器/设备（密钥留在本机 IDB ⇒ 解不开） | 键盘记录 / 屏幕截取 |

⇒ **仅建议个人专用设备开启**；**环境不支持（无 WebCrypto / 无 IndexedDB）⇒ 一律不记住**（fail-closed，**绝不退回明文存储**）。

### 15.2 硬约束（改动前必读）

1. **禁止**把口令以**明文**或**可逆混淆**（Base64 / XOR / 固定密钥）形式写进 `localStorage`/`sessionStorage`/Cookie；
2. 密钥**必须** `extractable=false` 且与密文**分离存放**（密钥进 IndexedDB）；
3. 默认**关**；开启必须**显式风险确认**；取消勾选必须**真删**（密钥 + 密文）；
4. 改密成功后**必须**清除已记住的口令；
5. 任何异常 / 不支持场景 ⇒ **不记住**（不得默默降级为明文）。

### 15.3 回归

`utils/loginPrefs.mjs` 单测 **15 例** —— 用户名：默认开 / 去空白 / 取消清值 / 空值不记 / 无 storage 不抛 / 隐私模式降级 / 键名稳定；
口令：**默认关** / **加密往返且落盘不含明文** / **密钥不可导出**（`exportKey` 必失败）/ **篡改密文 ⇒ 读回空串并自动清理** /
清除后读回空串 / 无 store·无 subtle ⇒ 一律失败且不抛 / 能力探测（Node 无 IndexedDB ⇒ 判为不支持）/ 风险文案含「XSS」与「个人专用设备」。
SSR 冒烟断言登录页含「记住用户名」与「记住密码（本机加密）」（SSR 无 WebCrypto+IDB ⇒ 渲染「不支持」分支并禁用，这正是 fail-closed 的体现）。
