# 入站鉴权 手动测试方案（**逐步骤 Runbook**）

> 版本：**v3.0**（2026-09-24）｜适用：**平台入站鉴权**（调用方鉴权 · 凭证池 · 平台设置 · 回调审计 · 灰度三态）
> 依据：《入站鉴权设计方案.md》**v1.2**（C1–C4 已落地：凭证池三级属主 / 方式归属接口 / 平台设置落库 / 审计凭证归因）
>
> **v2.0 → v3.0 变更（模型修订，必读）**：v1.1 的模型是「**先登记调用方，才准调**」；v1.2 改为
> 「**持有平台签发的凭证就准调**，登记是可选的精细管控」—— 因为调用方是**未知且持续新增的第三方**。
> 于是：
> ① 判定中心从「主体能否识别」变成「**凭证是否命中池**」（主体缺失/未知在开放集档**不再拦截**）；
> ② 鉴权方式从「挂在调用方档案上」改成「**挂在接口上**」（`CLIENT_AUTH` 绑定 → 平台默认 → 命中档案，三级回退）；
> ③ 凭证进**凭证池**（`INTERFACE` 接口专属 → `PLATFORM` 平台共享 → `CLIENT` 档案，**逐级短路**）；
> ④ 平台默认方式与「是否强制自报主体」**落库、页面可改、改后即时生效（无需重启）**；
> ⑤ 审计新增 **`credential_label` / `credential_fingerprint`**（共享凭证下唯一不可伪造的归因抓手）。
>
> **本方案有两条路径，按你的场景选一条走**：
> - **路径 A（v1.1 兼容档，第 2–5 阶段）**：登记调用方 + 给它配方式与凭证 —— 适用于**已知的少数业务系统**，可获得
>   「可验证身份」；`require_client_id=1`（默认）下行为与 v1.1 完全一致。
> - **路径 B（v1.2 凭证池，第 6–9 阶段）**：**不登记调用方**，页面发一把密钥即可调 —— 适用于**未知/持续新增的第三方**；
>   含平台设置、池隔离、单独吊销、开放集（`require_client_id=0`）四组验收。
>
> 建议：两条都走（约 45 分钟）；时间紧走**路径 B 的最小集**：S6.1 → S6.3 → S6.4 → S7.1 → S8.1（约 15 分钟）。
> 读者假设：你能打开 `http://localhost:5173`（前端）与 `http://localhost:8080`（后端），会用终端跑 `curl`
>
> **v1.0 → v2.0 的两处关键更正**（都会直接导致"测不出来"）：
> ① **「测试接口」绕过网关**（直调引擎）⇒ **它测不出鉴权、也不写审计**。v1.0 曾建议用它触发 —— **错**，本版改用**平台对外路径**（`curl`）。
> ② **「模拟回调」是自调网关** ⇒ **会过闸门** —— 所以内部令牌豁免（D-CA-17）是必须的，阶段四专门验它。
>
> **三种触发方式的对照（本方案最重要的前置知识）**：

| 触发方式 | 过鉴权闸门？ | 写审计？ | 能测什么 |
|---|---|---|---|
| 调**平台对外路径** `http://localhost:8080/{平台侧路径}` | ✅ **过** | ✅ | **鉴权全流程（本方案主用）** |
| 管理面「**测试接口**」 | ❌ **不过** | ❌ | 只能测链路 / 协议 / 映射，**测不出鉴权** |
| 管理面「**模拟回调**」 | ✅ **过**（自调网关） | ✅ | 鉴权 + 回调验签 + **内部令牌豁免**（阶段四） |
| 前置编排 / 补偿 worker | ❌ 不过 | ❌ | —— |

**页面入口（v3.0 新增）**：侧边栏「**◉ 入站鉴权**」页 = 平台设置（默认方式 / 强制自报主体 / 影响面）+ **凭证池**
（平台共享 / 接口专属 / 调用方档案三级属主）；接口详情的「**入站鉴权方式**」下拉 = 接口级方式覆盖。

**两条前置知识**：
- **`client-auth.mode` 是"启动期"属性**：改完**必须重启后端**才生效（单调用方的停用/启用则**无需重启**，见 S3.9）；
- **审计是异步批量写**（攒 50 条或 1 秒）⇒ 判定后**最多延迟约 1 秒**才出现在页面上，刷新/等一秒即可，**不是丢失**。

**建议时长**：完整 **约 30 分钟**（阶段一~四）；时间紧就跑**最小路径**：S1.1 → S1.4 → S2.1~S2.3 → S2.6 → S3.1~S3.5 → S4.3（约 15 分钟）。

### P5 搞清怎么切 `client-auth.mode`（**本方案唯一的"非页面"操作**）

## 8. 阶段七 · 池隔离与「逐级短路」—— 约 6 分钟

```bash
  -H 'X-Client-Id: '"$CLIENT" -H 'X-Api-Key: '"$KEY" -d '{}' | head -c 160; echo

# 3) 带 API Key（错密钥）
curl -s -X GET "$BASE$PATH_" -H 'Content-Type: application/json' \
  -H 'X-Client-Id: '"$CLIENT" -H 'X-Api-Key: wrong-key' -d '{}' | head -c 160; echo

# 4) 带凭证但没有主体（OPTIONAL 下应 40107；OFF 下应放行）
curl -s -X GET "$BASE$PATH_" -H 'Content-Type: application/json' -H 'X-Api-Key: whatever' -d '{}' | head -c 160; echo

# 5) HMAC 方式
TS=$(date +%s); BODY='{}'
SIG=$(printf '%s' "$TS.$BODY" | openssl dgst -sha256 -hmac '<HMAC 明文>' | awk '{print $2}')
curl -s -X GET "$BASE$PATH_" -H 'Content-Type: application/json' \
  -H 'X-Client-Id: PM-AUTH-HMAC' -H "X-Timestamp: $TS" -H "X-Signature: $SIG" -d '{}' | head -c 160; echo

# 6) 连续失败触发告警
for i in $(seq 1 12); do curl -s -o /dev/null -X GET "$BASE$PATH_" \
    -H 'Content-Type: application/json' -d '{}'; done; echo "已发 12 次失败请求"

# 7) 回调方向（错签名）
curl -s -o /dev/null -w "回调 → %{http_code}\n" -X POST "$BASE/<回调路径>" \
  -H 'X-Timestamp: '$(date +%s) -H 'X-Partner-Signature: deadbeef' -d '{"event_id":"evt-manual"}'
```

## 附 C：出问题时的取证四步

1. **看响应**：`code` 与 `msg` —— 错误码本身就是分流器（`40107` 主体问题 / `40108` 未配方式或无凭证 / `40100` 凭证或签名不匹配 / `40101` 时间戳 / `40103` IP）；
2. **看审计**：「接口监控 → 接入鉴权」按**主体或 IP** 筛 —— 能看到**方式、结果、错误码、来源 IP、说明**；
3. **看调用日志**：用审计行的 **`traceId`** 筛 —— 看这次调用**实际发了什么报文**（区分"没进来"与"进来了但上游失败"）；
4. **看库（终极）**：

```sql
SELECT * FROM access_auth_log ORDER BY id DESC LIMIT 5;                       -- 判定留痕
SELECT id,client_id,auth_adapter_id,status FROM client_app;                    -- 主体与方式
SELECT id,client_id,kind,status,activated_at,rotating_until
  FROM client_credential ORDER BY id DESC LIMIT 5;                             -- 凭证是否 ACTIVE
```

> 常见"假故障"：**没重启**（mode 不生效）、**凭证没激活**（ROTATING）、**用「测试接口」调**（不过闸门）、**审计没等 1 秒**。

## 附 D：常见误判（16 条）

| 现象 | 是缺陷吗 | 说明 |
|---|---|---|
| 改了 `mode` 但行为没变 | ❌ | 启动期属性，**必须重启**（单调用方停用/启用则免重启） |
| `OFF` 下审计里出现记录 | ❌ | 有意：`OFF` 仍写审计，用于观察期盘点存量调用方 |
| 用「测试接口」测不出鉴权 | ❌ | 它**直调引擎、不过网关**（见文首对照表） |
| 凭证生成了但带对头仍 `40100` | ❌ | 新凭证是 `ROTATING`，**要先点「激活」** |
| 报 `40108` 而不是 `40100` | ❌ | 该调用方**没配鉴权方式** ⇒ fail-closed（刻意不回退 Noop） |
| 报 `40107` 但调用方明明存在 | ❌ | 被**停用**了；或头名不是 `X-Client-Id`（可在适配器 params 改名）；或标识不是大写 |
| 审计里刚才的调用"查不到" | ❌ | 异步批量写，**最多延迟约 1 秒** |
| 平台自己「模拟回调」被拒 | ✅ **是缺陷** | D-CA-17 内部令牌豁免失效 |
| QPS / 日配额填了没生效 | ❌ | **本版本不生效**（列已预留，P2） |
| 配额/限流返回 `42901`/`42902` | ❌ | 那是**接入层防护**（应用维度），与鉴权（401xx）是两层 |
| 用 `127.0.0.1` 与 `localhost` 打开前端表现不同 | ❌ | CORS 按 Origin 放行（两者不同源） |
| 连续失败没触发告警 | ❌ | 需在 **5 分钟窗口内累计 10 次**（同主体；无主体时按 IP；v1.2 起键数有上限，超限折到 `overflow`） |
| 报 `40108` 而密钥明明对 | ❌ | **池里没有可用凭证**（未发放 / 未激活 / 已被吊销 / 用了别的池）—— 与「密钥错」`40100` 刻意分开 |
| 接口专属池填了却仍能拿平台池密钥调通 | ✅ **是缺陷** | 短路语义被实现成并集（应只看接口池那一级） |
| 页面改了平台设置但行为没变 | ⚠️ 先查两件事 | ① 是否点了「保存设置」；② 该接口是否**单独绑定了鉴权方式**（接口级优先于平台默认） |
| 开了开放集（关掉强制自报主体）后，审计里主体都是「自报未验证」 | ❌ | 这是**正确**的：自报主体不可信，只用于统计分组，**不能**当身份用于追责/配额 |
| 想在页面上把 `mode` 也改成 OFF | ❌ | `mode` **刻意留配置**（启动期）：应急总开关要「有意动作」= 重启，避免误点全局关鉴权 |
| 打开「入站鉴权」页提示 403 / 看不到菜单 | ❌ | 该页要 **ADMIN/OWNER**（`40305`）—— 只读角色（VIEWER）设计上不可达 |
| 点「保存设置」被拒 403 | ❌ | 改平台设置**仅 OWNER**（`40304`）；凭证发放/吊销等日常操作 ADMIN 即可 |
