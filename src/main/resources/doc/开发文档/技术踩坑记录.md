# 技术踩坑记录（Spring 7 / Jackson 3 / WireMock 3 适配经验）

> 记录 M1/M2 编码中踩过的 API 差异坑，全部为 Spring Boot 4.1 / Spring Framework 7 / Jackson 3 相对旧版的破坏性变化。
> **教训：Spring 7 大量沿用类名但改签名/改行为，凡用旧版记忆写代码，先查本文件再动手。**

## 1. Spring 7 内置 @Retryable（替代 spring-retry，差异巨大）

| 项 | 旧 spring-retry | Spring 7 内置（实际） |
|---|---|---|
| 包 | `org.springframework.retry.annotation` | `org.springframework.resilience.annotation`（启用注解 `@EnableResilientMethods` 同包） |
| 退避配置 | `@Backoff` 注解 | **内联属性**：`delay` / `multiplier` / `maxDelay` / `jitter` / `timeUnit`（无 @Backoff 类） |
| 重试条件 | `retryOn` | `includes` / `excludes` / `value` |
| 动态次数 | `maxAttemptsExpression` | `maxRetriesString`（SpEL）——**注意：见下方大坑，实际不可动态**；语义是**重试次数**（非总次数，total attempts = 1 + maxRetries） |
| 耗尽异常 | `RetryExhaustedException`（包装原异常） | **透传最后一次的原异常**（无包装） |

**写法范例**（独立 Invoker 类——AOP 自调用不触发代理）：

```java
@Retryable(includes = {HttpServerErrorException.class, TooManyRequests.class, ResourceAccessException.class},
        predicate = UpstreamInvoker.InterfaceRetryBudgetPredicate.class,  // 动态预算走 predicate（见下）
        maxRetries = RETRY_CAP,  // 注解值固定为上限；真实预算由 predicate 按次判定
        delay = 200, multiplier = 2, maxDelay = 2000, timeUnit = TimeUnit.MILLISECONDS)
public ResponseEntity<byte[]> invoke(...) { ... }
```

验证方式：`javap -classpath spring-context-7.0.8.jar org.springframework.resilience.annotation.Retryable` 看属性。

### 1.1 大坑：`maxRetriesString` 的 SpEL 并非每次调用求值（M4 缺陷修正）

`RetryAnnotationBeanPostProcessor.getRetrySpec` 把 `MethodRetrySpec` 按方法级 key 缓存
（`retrySpecCache: Map<MethodClassKey, MethodRetrySpec>`），`maxRetriesString` 的 SpEL
**只在首次调用该方法时求值一次**，之后所有调用复用缓存的 `maxRetries`——
「`maxRetriesString = "#{@bean.currentMaxRetries()}"` + ThreadLocal」方案**实际不生效**：
整个 JVM 内该方法的重试次数被首次调用时的 ThreadLocal 值固定
（M4 集成测试暴露：上下文首次调用是 maxRetries=0 的接口，后续 maxRetries=2 的接口不再重试）。

**正确姿势**：用 `@Retryable(predicate = Xxx.class)` 扩展点（每次尝试后回调，与 includes 取 AND）
承担真实预算——注解 `maxRetries` 固定为上限常量，predicate 内按 ThreadLocal 失败计数与
本次调用引擎设置的接口级预算比对。引擎须以 `beginRetryBudget(n)` / `endRetryBudget()`
包裹顶层调用（重置/清理 ThreadLocal，Tomcat 线程池复用防串账）。实现见 `UpstreamInvoker`。

## 2. Jackson 3（tools.jackson.*）

- 包名 `tools.jackson.*`，不是 `com.fasterxml.jackson.*`（依赖 `tools.jackson.dataformat:jackson-dataformat-xml`）。
- **`JsonNode.fields()` 已更名为 `properties()`**（ObjectNode 遍历）。
- Spring 注入的 `ObjectMapper` 是 `tools.jackson.databind.ObjectMapper`。

## 3. Spring 7 Web 客户端

| 坑 | 结论 |
|---|---|
| `HttpClientErrorException.TooManyRequests` 构造器**全部私有** | 用静态工厂 `HttpClientErrorException.create(statusCode, statusText, headers, body, charset)`——按状态码返回对应子类（429 → TooManyRequests 实例），重试类型匹配不受影响 |
| `JdkClientHttpRequestFactory` **无 `setConnectTimeout`** | 只有 `setReadTimeout(Duration)` |
| `@RequestBody` 无 `value` 属性 | 只有 `required`；显式命名只用于 `@PathVariable` / `@RequestHeader` |
| `HttpHeaders.addAll(MultiValueMap)` 不适用 | 逐条目添加：`spec.headers().forEach(h::addAll)`（`addAll(String key, List<String> values)`） |
| **声明式客户端（@HttpExchange）URI 模板变量被路径编码** | 完整 URL（含 `://`）作为 `{url}` 变量时经 DefaultUriBuilderFactory 展开被编码（`://` → `%3A%2F%2F`），scheme 丢失报 `URI with undefined scheme`。**动态完整 URL 场景不用声明式客户端**，改用 `RestClient` 直调：`restClient.method(m).uri(URI.create(url)).headers(...).body(...).retrieve().toEntity(byte[].class)`（`uri(URI)` 不经过模板展开）。详见 M0-03 C1 验证点结论 |
| **RestClient 直调默认对 4xx/5xx 抛异常**（声明式客户端返回 ResponseEntity 不抛） | 用 `defaultStatusHandler(HttpStatusCode::isError, (req, resp) -> {})` 禁用，统一返回 ResponseEntity 由引擎分类（4xx 死信 / 429·5xx 由 Invoker 手动抛触发重试） |
| 注解按参数名匹配（`@PathVariable` 等）依赖 `-parameters` | Maven 默认不开，**显式命名** `@PathVariable("url")` 最稳（不过 URI 模板坑仍然存在，见上） |

## 4. WireMock 3（测试）

- `equalTo("...")` 替代旧 `equalToPattern`。
- verify 用 `postRequestedFor(urlEqualTo("/path"))` 返回 `RequestPatternBuilder`（`post(...)` 返回 MappingBuilder，不能直接 verify）。
- **请求计数跨测试累积** → 每个测试 `@BeforeEach` 里 `wireMock.resetAll()`（清 stub + 计数）。

## 5. Maven / 构建

- **`mvn test` 不清旧产物**：删源文件后 target/classes 里的旧 class 残留会被 Spring 扫描装配（旧 demo 的 CallbackController 曾导致启动 NPE）。改结构后务必 `mvn clean test`。
- Lombok 在 JDK 25 下的 `sun.misc.Unsafe` 警告是噪音，可忽略（JDK 21 下消失）。
- 机器无 `mvnw`，Maven 路径 `~/Documents/program/apache-maven-3.9.16`（PATH 需自配）。

## 6. 测试与种子数据

- **列表接口不带子表**（`InterfaceService.list()` 的 params 等恒空）——断言/校验子表必须走 `detail()`；SeedDataInitializer 完整性校验也用 detail。
- **集成测试数据自清理**：cleanup 必须先级联删测试接口（6 子表）再删应用，否则残留接口污染后续测试（唯一键冲突）。
- **乐观锁测试要真跑两遍 update**：M1 曾把响应的 model 类型子表误塞进请求 DTO（ParamRow vs ParamDto），类型不匹配编译失败。
- `UnifiedModel.get()` 契约上把 NULL 标量视为「不存在」——测试要区分「写了 null」与「没写」时直接读 `root()` 字段。

## 7. 排查方法论

- 引擎 catch-all 分支（"平台内部错误"）会吞根因：**log.error 带完整堆栈**，排查时用 `mvn test -Dtest=XxxTest 2>&1 | grep -B2 -A15 "执行异常"` 快速定位。
- Spring 7 新 API 不确定时：`javap -classpath <jar路径> <全限定类名>` 看注解属性/方法签名；`unzip -l <jar> | grep 关键词` 找类位置。
