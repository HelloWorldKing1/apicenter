# 管理面账号登录设计方案（v1.0 · 2026-09-18）

> **定位**：把此前明确推迟的「B 类 P0 —— 管理面无鉴权」补上，**只做认证**（登录 / 注册 / 退出 / 改密），
> **不做权限**（无角色、无资源授权）。范围严格限定在管理面 REST（`/api/admin/**`）。
>
> **不涉及**平台对外接口路径（`/{platformPath}`，出站调用与入站回调）—— 那是「调用方鉴权」，
> 属另一特性（《API中心设计方案.md》§1.2 / §5.3），本方案**一行都没动**它。
>
> 落地状态：**已落地**（2026-09-18）。表 `admin_user` / `admin_session`（第 21、22 张）已应用到开发库；
> 后端 19 例 + 前端 9 单测 / 1 SSR 用例；接口与错误码见 §4。

---

## 1. 目标与非目标

| | 内容 |
|---|---|
| **目标** | ① 账号登录（不透明 Bearer 令牌）② 注册（含「首个账号」首次初始化）③ 退出（即时失效）④ 修改密码（吊销其他会话）⑤ 未登录访问管理面被拦（HTTP 401 + 统一信封）|
| **非目标** | 角色/权限/菜单裁剪、用户管理界面（列表/禁用/删除）、找回密码（邮件）、SSO/OAuth、多租户、操作审计表、多实例共享会话（单实例内存+DB 已够；多实例天然共享，因为令牌在 DB） |

## 2. 决策记录（D-AUTH-*）

| # | 决策 | 理由 / 备选 |
|---|---|---|
| D-AUTH-1 | **不透明 Bearer 令牌**（DB `admin_session`，只存 SHA-256 摘要） | 备选 ①Cookie Session：引入 CSRF 面、跨域/代理联调更绕；备选 ②JWT：需引依赖且**无法即时吊销**。令牌方案还能直接 `curl -H 'Authorization: Bearer …'` 复现问题 |
| D-AUTH-2 | 口令 **PBKDF2-HMAC-SHA256**（JDK 自带，120k 迭代，每用户随机盐，格式自描述 `pbkdf2$iter$salt$hash`） | 零新增依赖；与 `CryptoService`（可逆 AES，凭证签名要重算明文）刻意分开：口令必须**不可逆** |
| D-AUTH-3 | 保护范围 = `/api/admin/**` | 平台对外路径不动（调用方鉴权是另一特性）；静态资源与 `/actuator/health` 放行 |
| D-AUTH-4 | 令牌 TTL 12h + **惰性续期**（距上次续期 > 1h 才写一次） | 避免「每请求一次 UPDATE」的写放大；`renewIfDue` 把判据放进 SQL（一条语句，不是读+写两次往返） |
| D-AUTH-5 | 登出**删行**、改密**吊销该账号其他会话**（当前会话保留） | 即时失效不依赖 TTL；改密后自己不被踢出 |
| D-AUTH-6 | 开放注册（`allow-register` 默认 true），但**系统无任何账号时永远允许** | 用户明确要注册功能；「首个账号」规则避免把管理员锁在门外。生产建议建号后置 false（§6.4） |
| D-AUTH-7 | 暴力破解：连续失败 5 次 → 锁定 5 分钟（成功登录清零，锁定期内**密码正确也拒**） | 计数落库（多实例同口径）；锁定不影响其他账号 |
| D-AUTH-8 | 登录失败**不区分**「用户不存在 / 密码错」，文案统一 | 防账号枚举；但会给出「还可尝试 N 次」（内部工具，可观测性优先于极致隐匿） |
| D-AUTH-9 | 开关 `auth.enabled`（默认 true）；集成测试里直连管理面 HTTP 的类统一置 false | 既保留既有用例语义，又让 `AuthIntegrationTest` 用默认值证明「过滤器真的生效」 |
| D-AUTH-10 | **`login()` 刻意不加 `@Transactional`** | 见 §10 坑 1：加了会把「失败计数」一起回滚，锁定形同虚设 |

## 3. 数据模型（第 21 / 22 张表）

```sql
admin_user(id, username UNIQUE, display_name, password_hash, status, failed_attempts,
           locked_until, last_login_at, password_updated_at, created_at, updated_at)
admin_session(id, user_id, token_hash UNIQUE, client_info, created_at, last_seen_at,
              renewed_at, expires_at)
```

- 命名规则：`username` 3-32 位小写字母/数字/`_` `.` `-`，**统一小写存储**（避免大小写混淆）；口令 8-64 位且**同时含字母与数字**。
- `admin_session` 只存**摘要**：库泄露 ≠ 可登录（与 M0-04「凭证不落明文」同一纪律）；`client_info` 记 IP + UA 摘要（诊断），截断 200 字符。
- 无外键（全库一致），`user_id` / `expires_at` 建索引；过期会话由**登录时机会式清理**（不为一张几乎不增长的表引入调度任务）。
- 删除策略：删账号 → 联删其会话（`schema.sql` 删除约定已登记）。

## 4. 接口清单（`/api/admin/auth/*`）

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/status` | **豁免** | 登录页引导：`{enabled, hasUser, allowRegister}`（`hasUser=false` → 首次初始化，登录页默认切到「注册」） |
| POST | `/login` | **豁免** | `{username, password}` → `{token, expiresAt, user}` |
| POST | `/register` | **豁免** | `{username, password, displayName?}` → 同上（**注册即登录**，少一步） |
| GET | `/me` | 需登录 | 当前账号 `{id, username, displayName, lastLoginAt}` |
| POST | `/password` | 需登录 | `{oldPassword, newPassword}` → 校验原密码 → 更新 → **吊销其他会话** |
| POST | `/logout` | 需登录 | 删除当前令牌行（即时失效） |

**错误码**（新增；`40100/40101` 已被入站回调验签占用，故从 40104 起）：

| 码 | HTTP | 含义 |
|---|---|---|
| 40104 | 401 | 未登录 / 令牌缺失·无效·过期 |
| 40105 | 401 | 用户名或密码错误 / 原密码不正确 |
| 40106 | 401 | 账号已锁定（含剩余分钟数） |
| 40301 | 403 | 注册已关闭 |
| 40901 | 409 | 用户名已存在 |
| 40001 | 400 | 用户名或口令不符合规则（长度/字符集/字母数字混合） |

## 5. 守卫（后端过滤器 + 前端路由守卫）

**后端 `AdminAuthFilter`**（`OncePerRequestFilter`，`@Order(HIGHEST_PRECEDENCE + 10)`）：

```
非 auth.enabled            → 放行
非 /api/admin 前缀         → 放行（对外接口路径 /actuator/health/静态资源）
/auth/{login,register,status} → 放行（登录页自身要能访问）
OPTIONS（CORS 预检）        → 放行  ← 2026-09-18 CORS 事故同类坑：拦掉会让浏览器所有写操作失败
无 Authorization: Bearer    → 401 + {code:40104}
令牌无效/过期               → 401 + {code:40104}
通过                        → 请求属性注入账号 + 令牌摘要（Controller 直接取用）
```

**前端**：

- `api/http.js`：请求自动带 `Authorization`；响应 `401`/`40104` 且**非** `/auth/*` 端点 → 清登录态 + 整页跳 `/login?redirect=<原路径>`（整页跳转而非 router，避免 http ↔ router 循环依赖）；
- `router/index.js`：已登录访问 `/login` → 回概览；未登录访问业务页 → 带 `redirect` 跳登录页；`auth.enabled=false` 时放行（前后端口径一致）；
- `utils/auth.mjs`：令牌/用户存取（storage 可注入，便于单测；**SSR 能力守卫**）、表单预校验（与后端同规则）、`redirectTarget` 只接受站内相对路径（**防开放重定向**）。

## 6. 安全口径

1. **口令**：不可逆摘要（PBKDF2 120k + 随机盐 + 常量时间比较）；任何接口、日志、错误信息都不回显口令；库里存的是 `pbkdf2$…`。
2. **令牌**：32 字节 `SecureRandom` → Base64URL；库内只有 SHA-256 摘要；明文只在登录/注册响应出现一次。
3. **会话生命周期**：TTL 12h（惰性续期，最长有效期内可持续使用）；登出 / 改密 / 过期即失效；`admin_session` 过期行机会式清理。
4. **注册风险与关闭方式**：默认开放（用户要求）。生产建议：`app.api-center.auth.allow-register: false`（首个账号仍可注册，之后新增账号由 DBA 或后续「账号管理」能力承担）。
5. **未做的加固（诚实登记）**：无 IP 维度限流（只有账号维度锁定）、无 MFA、无密码历史、无登录审计表（仅 `log.info/warn`：成功/失败/锁定/改密）、令牌不可滚动刷新（到期需重登）。

```yaml
app:
  api-center:
    auth:
      enabled: true                 # false = 完全不校验（集成测试 / 线上应急回退）
      allow-register: true          # false 时仍允许「首个账号」初始化
      session-ttl-hours: 12
      renew-interval-minutes: 60    # 惰性续期粒度（写放大控制：≤1 次写/会话·小时）
      max-failed-attempts: 5
      lock-minutes: 5
```

## 10. 落地踩坑（真坑，务必别踩回）

1. **`login()` 加 `@Transactional` = 失败计数被回滚**（实测）：登录失败要抛 `BizException`，同一事务里先前写的
   `failed_attempts + 1` 会一起回滚 → 连续失败次数永远是 1，**锁定形同虚设**（`连续失败达阈值_锁定且正确密码也被拒` 用例抓到）。
   结论：这种「写入 + 抛异常」的流程**不要挂事务**，或让计数写走 `REQUIRES_NEW`。
2. **CORS 预检必须放行**：`OPTIONS /api/admin/**` 不带 `Authorization`，过滤器拦掉会让浏览器**所有写操作**失败
   （与 2026-09-18 的 CORS 单 Origin 事故同一类症状：请求根本不进引擎、无 call_log）。
3. **Frontend 单测/SSR 的能力守卫**：`utils/auth.mjs` 顶层访问 `localStorage` 必须做 `typeof` 守卫，否则 SSR 冒烟直接抛；
   冒烟的 `ElStub` 未声明 `props` ⇒ 表单标签（`label`）落在 **attrs** 上（`attrs.label`），不是 `props.label`。
4. **开发库即测试库**：`AuthIntegrationTest` 会创建真实账号 → 用例内用随机后缀 + `@AfterEach` 清理自己创建的账号与会话。

## 11. 验收速查（curl）

```bash
BASE=http://localhost:8080/api/admin

# 首次初始化（无账号时）：注册即登录
TOKEN=$(curl -s -X POST $BASE/auth/register -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"Passw0rd","displayName":"管理员"}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["data"]["token"])')

curl -s $BASE/auth/me -H "Authorization: Bearer $TOKEN"            # 当前账号
curl -s $BASE/apps                                                # 40104（未带令牌）
curl -s $BASE/apps -H "Authorization: Bearer $TOKEN" | head -c 120 # 正常
curl -s -X POST $BASE/auth/password -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"oldPassword":"Passw0rd","newPassword":"NewPassw0rd"}'     # 改密（吊销其他会话）
curl -s -X POST $BASE/auth/logout -H "Authorization: Bearer $TOKEN" # 退出
```

界面：浏览器打开管理面 → 未登录自动跳 `/login`；首次使用按提示创建账号 → 顶栏右侧可改密 / 退出。
