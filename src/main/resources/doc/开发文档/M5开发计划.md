## 2. 设计定稿（编码前必读）

### 2.1 D-M5-1 接口版本快照与回滚

**快照时机与内容**：

- **创建接口** → version=1 + 写首快照；**每次成功的配置更新**（`PUT /api/admin/interfaces` 全量替换路径）→ version+1 + 写新快照，`change_note` 取请求参数（前端「变更说明」输入，可空）；**status 流转（发布 / 下线）不生成版本**（生命周期不是配置变更）；
- `config_json` 结构（Jackson 序列化，**完整可重建**）：

```json
{
  "main":     { "code": "...", "name": "...", "ifType": "...", "method": "...", "path": "...",
                "protocolIn": "...", "protocolOut": "...", "upstreamPath": "...", "callbackUrl": "...",
                "appId": "...", "groupId": 0, "timeoutMs": 3000, "maxRetries": 4, "desc": "..." },
  "params":    [ { "side": "...", "name": "...", "type": "...", "required": true, "sample": "...", "sortOrder": 0 } ],
  "bodies":    [ { "side": "...", "bodyType": "...", "raw": "...", "form": "..." } ],
  "mappings":  [ { "source": "...", "op": "...", "target": "...", "param": "...", "nullStrategy": "...", "sortOrder": 0 } ],
  "fieldDefs": [ { "kind": "...", "name": "...", "type": "...", "desc": "...", "sortOrder": 0 } ],
  "bindings":  [ { "role": "...", "adapterId": "...", "version": "..." } ]
}
```

- **不含 status**（回滚不动生命周期，见下）；**含 appId（评审缺陷修订，2026-09-04）**——已核实 `InterfaceService.update` 走 `validateBelong` + `updateWithVersion`，**app_id / group_id 均可在更新时修改**（validateBelong 仅校验组属于所选应用，无归属固定约束）：快照若缺 appId，换过应用的接口回滚会恢复到错误归属。

**回滚语义**：

- `POST /api/admin/interfaces/{id}/rollback`，body `{targetVersion, operator, reason, currentVersion}`：
  1. 校验目标快照存在（不存在 → 40402 语义错误信封）、currentVersion 乐观锁（并发更新冲突 → 40001「配置已变更，请刷新」）；
  2. 以快照内容走 **InterfaceService 既有全量替换路径**（复用 update 的类型互斥校验 / 子表全删全插 / 乐观锁）——回滚不旁路校验；
  3. **version = 当前 + 1（历史只增，不回退号码）**；新快照 `change_note = "回滚至 v{targetVersion}（operator=xxx, reason=...）"`（operator/reason 拼入 change_note，**不新增审计表 / 列**——M4 的 reconcile_audit 为对账专用，不扩语义）；
  4. **status 保持当前生命周期状态**（快照不含 status）；回滚后 `path` 若与现有其他接口冲突（唯一键）→ 错误信封提示先处理冲突接口（校验在替换路径内自然发生）；
  5. 回滚即配置变更 → 触发链缓存失效（D-M5-2）→ **路由行为即时生效**；
  6. **回滚边界（评审补充）**：只恢复接口配置与绑定引用——**适配器定义自身（params / 版本）不在回滚范围**（适配器版本化是 D-M5-2 独立维度）；快照引用的适配器若届时已停用 / 缺失，装配按 D-M5-2 矩阵 #4 逐层回退 + warn，不阻断。
- **版本查询**：`GET /api/admin/interfaces/{id}/versions`（id/version/change_note/created_at 倒序分页）+ `GET .../versions/{version}`（config_json 详情）。

**前端**：接口列表 / 详情加「版本历史」入口——弹窗列表（版本号 / 变更说明 / 时间）+ 查看快照 JSON + 「回滚到此版本」按钮（operator / reason 确认框，二次确认）。

### 2.2 D-M5-2 适配器灰度绑定与链缓存事件失效

**绑定 version 解析矩阵（定稿）**——绑定行（接口级覆盖或应用级默认）携带 `adapter_id` + 可空 `version`：

| # | 条件 | 解析 | 说明 |
|---|---|---|---|
| 1 | adapter_id 空 | 应用默认（应用默认空 → 平台默认 Noop 直通） | 现状行为 |
| 2 | adapter_id 非空、version 空、该行 enabled=1 | 该 adapter_id 行 | 现状行为 + **enabled 校验（新增）** |
| 3 | adapter_id 非空、version 非空 | 按「该行 impl + 指定 version + enabled=1」定位行 | **灰度路径**：同 impl 多版本共存，绑定指定版本 |
| 4 | 目标行停用或缺失 | **逐层回退 + log.warn**：接口绑定不可用 → 应用默认；应用默认不可用 → 平台默认 Noop | 2026-09-04 评审拍板「回退 + 可观测」而非报错拒绝（灰度目标缺失属配置事故，阻断会放大为全接口不可用） |

**「停用即回退」（评审新增，闭环 M1/M2 遗留缺口）**：现状 `resolveBound` 不校验 adapter.enabled，「停用」在运行时不生效——本计划统一 #2 与 #3 两条路径的 enabled 校验，停用即视为不可用并按 #4 逐层回退；注意既有「绑定行存在但 adapter_id 为空 = 显式继承应用默认」语义（ChainEngine 注释，管理面前端恒提交空绑定行）不受影响。

**留痕（三通道，不加列不加表）**：

1. **链装配日志**：每次装配 `log.info` 输出 roles → `adapterId:impl:version` 明细（含 traceId）——ChainEngine 装配处一条日志，量 = 链缓存未命中频次（低）；
2. **Observation span tag**：M4 已有链 span，追加 tag `adapter.{role} = {id}:{impl}:{version}`（版本为低基数，可作维度）；
3. **接口测试端点附 chainTrace**：`POST /api/admin/interfaces/{id}/test` 响应 data 内增加 `chainTrace`（本次装配明细数组：role / adapterId / impl / version）——**灰度验证工具**：改绑定后点「测试接口」即可肉眼确认路由到目标版本，无需查日志。

**链缓存事件失效（M2 评审 #17 闭环）**：

- 管理面配置变更 → 发布 Spring 应用事件 `ConfigChangedEvent{scope, interfaceId?}`；`ChainEngine` 监听：
  - scope=INTERFACE → 精准 `chainCache.remove(interfaceId)`；
  - scope=ADAPTER / APP（适配器定义 / 应用默认绑定变更，影响面不定）→ **全清 `chainCache.clear()`**（重建成本低、正确性优先）；
- 发布点（逐一核对，漏一处即灰度不生效）：`InterfaceService`（update / rollback / publish / offline / delete）、`AdapterService`（增改 / 启停 / 删）、`AppService`（默认三绑定变更 / 启停）；TTL 5 分钟保留为兜底（M0-01 §7）；
- **灰度即时生效依赖此**（测试断言：改绑定后立即调用，新版本语义生效，不等 TTL）。

**前端**：绑定编辑处（接口详情适配器绑定区 + 应用默认三绑定）version 下拉——「跟随当前版本（空）」+ 同 impl 的 enabled 版本列表。

## 5. 手动验收方案（约 25 分钟）

> 全程管理面 + curl + 查库；WireMock 复用 `m4-manual-stubs`（`/breaker-supplier` 转为恒 200 作正常上游）。

**阶段一：版本快照与回滚（约 10 分钟）**

1. 选演示接口（如 M3 阶段一的 IF-XML-01）→「版本历史」→ 看到既有版本列表；编辑映射（改一条 rename 的 target）+ 填变更说明 → 保存 → 版本列表 +1、change_note 显示；
2. 回滚到修改前版本（弹窗填 operator / reason，二次确认）→ curl 调用 → 出站报文恢复旧 target 字段名（WireMock / 查库 out_payload 断言）→ 版本历史新增一条「回滚至 v{n}」且版本号只增；查库：
   ```sql
   SELECT version, change_note, created_at FROM interface_snapshot
   WHERE interface_id = ? ORDER BY version DESC LIMIT 3;
   ```

**阶段二：灰度绑定（约 10 分钟）**

1. 适配器管理建同 impl 两个版本信封适配器（如「信封-演示 v1」codeField=code、「信封-演示 v2」codeField=status，name 带版本后缀区分）；
