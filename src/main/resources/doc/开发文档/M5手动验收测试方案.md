# M5 手动验收测试方案（版本快照 / 回滚与适配器绑定切换）

> 用途：M5 版本快照 / 回滚与适配器绑定切换（D6'：绑定即实例）的手动端到端验收（补充 M5IntegrationTest 的平台实操验证），全程约 30 分钟。
> 本方案按 M5 实施后的实际行为校准（D-M5-1 / D-M5-2，2026-09-07 编码落地；D-M5-3 压测部分含生产加固验证步骤）。
> 前置：M5.1 / M5.2 代码已跑通全库 174 @Test（自动化已覆盖 S1-S6）；本方案验证**管理面交互 + 运行时即时性 + 留痕**三件自动化难以覆盖的事。
> 模拟供应商用本地 WireMock（复用 `m4-manual-stubs`；压测场景 1 可将 `/breaker-supplier` 转恒 200 作正常供应商，或自建 200 stub）。

## 验收目标总览

| 能力 | 白话解释 | 在哪验 | 定稿 |
|---|---|---|---|
| 版本快照 | 每次保存自动生成新版本，改动可追溯（含变更说明） | 阶段一 | D-M5-1 |
| 回滚 | 配置出错一键回到历史版本；版本号只增不倒退、发布状态不受影响 | 阶段一 | D-M5-1 |
| 绑定切换 | 同一种适配器装多个实例（推荐不同 version），接口绑定某实例（adapter_id），换绑定**立即生效**（不等缓存 TTL） | 阶段二 | D-M5-2/D6' |
| 绑定容灾 | 绑定实例缺失 / 停用 → 自动逐层回退 + 日志告警，不打死接口 | 阶段二 | D-M5-2 |
| 留痕三通道 | 装配日志 / span tag / 测试接口 chainTrace | 阶段二 | D-M5-2 |
| 压测与加固 | 读放大收益验证 + 凭证唯一索引（PolarDB 兼容） | 阶段三 | D-M5-3 |

## 前置：启动（三个终端，同 M4）

```bash
# 终端 1：后端
mvn spring-boot:run                       # 8080；种子默认不自动导入——需要时 POST /api/admin/seed/import

# 终端 2：前端
cd frontend && npm run dev                # http://localhost:5173

# 终端 3：本地 WireMock（复用 m4 stub 目录；若 M4 验收已完成可自建恒 200 stub）
java -jar ~/.m2/repository/org/wiremock/wiremock-standalone/3.9.1/wiremock-standalone-3.9.1.jar \
  --port 18080 --root-dir src/test/resources/m4-manual-stubs
```

健康确认：
```bash
curl -s -X POST http://localhost:18080/echo-ok      # 预期 {"ok":true}（stub 全部只认 POST）
curl -s http://localhost:8080/actuator/health       # UP
```

## 阶段一：版本快照与回滚（约 10 分钟）

**步骤 1：建演示接口**（应用管理 → 新建 `M5DEMO`，服务地址 `http://localhost:18080`，鉴权留空 → 启用；接口管理 → 新建并发布）：

| 字段 | 值 |
|---|---|
| 接口标识 / 名称 | `IF-M5-VER` / M5 版本演示 |
| 类型 / 方法 | OUTBOUND / POST |
| 平台侧路径 | `/m5/ver` |
| 供应商接口路径 | `/echo-ok` |
| 字段映射 | 加一条：入站 `state` → rename → 出站 `order_state` |

> 前端保存时底部「变更说明（可选）」为空即可。保存后「版本」显示 v1.0。

**步骤 2：改配置生成 v1.1 + 变更说明**：
接口列表 → 详情 → 编辑 → 把映射 op 改为「枚举映射」，param 填 `PAID→已支付` → 变更说明填 `改枚举映射` → 保存。

- 预期：版本变 **v1.1**；详情 → 「版本历史」→ 两条记录（v1.1「改枚举映射」、v1.0 无说明）。

**步骤 3：回滚到 v1.0（二次确认）**：
版本历史 → v1.0 行 → 「回滚到此版本」→ 弹窗操作人填 `admin`（必填）、依据填 `演示回滚` → 确认回滚。

- 预期：版本变 **v1.2**（每次变更/回滚 +0.1，只增不回退）；版本历史新增一条「回滚至 v1.0（operator=admin, reason=演示回滚）」；**状态仍「已发布」**（回滚不动生命周期）；
- curl 调用确认回滚后映射恢复 rename 语义：
```bash
curl -s -X POST http://localhost:8080/m5/ver -H "Content-Type: application/json" \
  -d '{"state":"PAID"}'
```
  WireMock 收到请求 body 应为 `{"order_state":"PAID"}`（不再是「已支付」）——可看 WireMock 请求日志或查库 out_payload。

**步骤 4：查库（三要素核对）**：
```sql
SELECT version, change_note, created_at FROM interface_snapshot
WHERE interface_id = (SELECT id FROM interface WHERE code='IF-M5-VER') ORDER BY version DESC LIMIT 3;
-- 预期：v1.2「回滚至 v1.0（operator=admin, reason=演示回滚）」/ v1.1「改枚举映射」/ v1.0 NULL
SELECT status FROM interface WHERE code='IF-M5-VER';            -- PUBLISHED（未被回滚改写）
```

**步骤 5（可选）：冲突与缺失拒绝**：
- 版本历史再对 v1.0 点回滚、但把操作人留空 → 前端拦截提示「请填写操作人」；
- 若想验证乐观锁：另开一个浏览器 tab 同接口编辑页 → 先 tab A 保存 → 回 tab B 保存 → 预期 40001「配置已被他人修改，请刷新」。

## 阶段二：绑定实例切换与即时生效（D6' 取代灰度版本路由，约 12 分钟）

> D6' 变更（2026-09-08）：同 (impl, version) 允许多启用、adapter.name 全表唯一；**绑定即实例**——绑定时只选实例（adapter_id），无版本下拉，version 仅记录不路由。本阶段验证：切换实例即时生效 + chainTrace + 停用/缺失容灾。

**步骤 1：建同 impl 双版本信封适配器**（适配器管理 → 新建两次，类型「报文」）：

| 字段 | 适配器 A（v1） | 适配器 B（v2） |
|---|---|---|
| 标识 | `ADP-ENV-1` | `ADP-ENV-2` |
| 名称 | 信封演示 v1 | 信封演示 v2 |
| 实现 | 信封报文适配器（EnvelopeMessageAdapter） | 同 |
| 版本 | `1.0` | `2.0` |
| 参数·信封字段(envelope) | `data` | `data` |
| 参数·成功码字段(codeField) | `code` | `status` |
| 参数·成功值(successValue) | `0` | `ok` |
| 参数·消息字段(messageField) | `message` | `message` |
| 启用 | 是 | 是 |

> 关键验证：**同 impl 双实例可同时启用**（示例用不同 version 1.0/2.0；同 (impl, version) 同版本亦可并存，D6' 已放开）——仅要求**名称不重复**（adapter.name 全表唯一）。

**步骤 2：接口绑定 ADP-ENV-1，先验证剥壳语义**：新建接口 `IF-M5-GRAY`（OUTBOUND，平台路径 `/m5/gray`，供应商接口路径 `/echo-ok`）→ 高级 tab「报文适配器」选 `ADP-ENV-1`（已无绑定版本下拉——绑定即实例）→ 保存发布。

WireMock 侧先把 `/echo-ok` 响应改为含双码信封的 JSON（区分 v1/v2 语义）：
```bash
curl -X POST http://localhost:18080/__admin/mappings -H "Content-Type: application/json" -d '{
  "priority": 1, "request": {"method": "POST", "url": "/echo-ok"},
  "response": {"status": 200, "jsonBody": {"data": {"v": 1}, "code": "0", "status": "bad"}}}'
curl -s -X POST http://localhost:8080/m5/gray -H "Content-Type: application/json" -d '{}'
# 预期：code=0、data={"v":1}（v1 按 code=0 判成功并剥出 data；status 字段不出现在 data）
```

**步骤 3：改绑 ADP-ENV-2 → 立即生效 + chainTrace（切换核心）**：编辑接口 → 高级 tab「报文适配器」改选 `ADP-ENV-2`（不再有版本下拉——切换 = 换实例）→ 保存（变更说明可填 `切 v2`）。

换供应商信封为 v2 语义（code=x、status=ok）：
```bash
curl -X POST http://localhost:18080/__admin/mappings -H "Content-Type: application/json" -d '{
  "priority": 1, "request": {"method": "POST", "url": "/echo-ok"},
  "response": {"status": 200, "jsonBody": {"data": {"v": 2}, "code": "x", "status": "ok"}}}'
```
- 点接口详情「**测试接口**」→ 发送 → 响应 data 出现 **chainTrace**：`MESSAGE → ADP-ENV-2:EnvelopeMessageAdapter:2.0`（留痕通道 3，强制实时解析）；
- **立即** curl（不等 5 分钟）：
```bash
curl -s -X POST http://localhost:8080/m5/gray -H "Content-Type: application/json" -d '{}'
# 预期：code=0、data={"v":2}——配置变更事件已失效链缓存，切换即时生效
```

**步骤 4：绑定容灾（回退 + warn，不阻断）**：停用绑定实例 `ADP-ENV-1`（等价于实例缺失）→ curl → 预期**自动回退**（应用默认/Noop 兜底，响应按未剥壳原样，不 502/500）：
- 后端日志可见「链装配 …」前 warn「适配器绑定回退：role=… 绑定 adapter=ADP-ENV-1 不可用（缺失 / 停用）→ 应用默认」；
- **重新启用** `ADP-ENV-1` → curl → 恢复信封剥壳（不再 warn）。

**步骤 5：装配日志与 span tag（留痕通道 1/2）**：
- 终端 1 后端日志：每次链缓存未命中（改绑定后首次调用）出现一行「链装配 … 绑定解析 → MESSAGE=ADP-ENV-… AUTH=PLATFORM-DEFAULT:NoopAuthAdapter:1.0」（含 traceId）；
- span tag 验证（可选）：Prometheus `apicenter_chain_stage_seconds` 或链路采集端看 `adapter.MESSAGE = ADP-ENV-2:EnvelopeMessageAdapter:2.0`。

## 阶段三：压测与生产加固（约 8 分钟）

**步骤 1：凭证唯一索引兼容性验证（D-M5-3 生产加固）**：
```sql
-- 先小样本验证 PolarDB 兼容性（MySQL 8 函数索引；5.7 不支持）
ALTER TABLE app_credential ADD UNIQUE KEY uk_credential_live
  ((app_id), (kind), (IF(status IN ('ACTIVE','ROTATING'), status, NULL)));
```
- 成功 → 已落地；报错（语法不支持）→ **降级方案文档化**：记录「PolarDB 不支持函数索引，维持应用层 synchronized + 文档明示」（M5 计划 §2.3 允许，不阻塞出口）。

**步骤 2：压测冒烟（场景 1 / 场景 2，脚本随仓库 `src/test/resources/m5-load/`）**：
```bash
# 场景 1：出站吞吐（先把供应商置为本地 WireMock 恒 200 直通接口）
wrk -t4 -c100 -d30s -s src/test/resources/m5-load/wrk-envelope.lua \
  --header "Content-Type: application/json" http://localhost:8080/<你的出站接口路径>
# Monitor 页看 QPS/P99；prometheus 看 calllog.dropped（应恒 0）
# 场景 2：QPS 限流阈值（把应用 qps_limit 设 50 后）
wrk -t4 -c200 -d30s -s src/test/resources/m5-load/wrk-envelope.lua http://localhost:8080/<限流接口路径>
```
- 预期：错误率 < 0.5%、无 5xx、`apicenter.calllog.dropped` 为 0；42901 出现（场景 2）且运行表无污染；
- **读放大收益抽查**（M5.2 烘焙后）：同压测下后端日志无逐请求「findMappings/绑定查询」密集读——配置读取已收敛到链缓存未命中（一次性装配）；远程库延迟下 P99 应低于 M4 基线（DB 读放大消除）。
- 结果记入 `doc/开发文档/M5压测报告.md`（未做项列调优清单，同步送达决策场景 5 另行按需执行）。

**步骤 3：全功能 walkthrough（M1–M5 收口回归）**：应用（含弹窗内联凭证）/ 分组 / 接口 / 适配器 / 凭证轮换（详情抽屉高级轮换）→ 黄金用例 G1-G4 → 入站回调 B1-B6 → Monitor 五面板 → 版本历史与绑定切换——全部可用即 M5 出口达成。

## 验收对照

| 步骤 | 对应定稿 / 出口 |
|---|---|
| 一 | 快照生成 + 变更说明可追溯 + 回滚一致性 + 版本只增 + status 不变 + 40403/40001 语义（D-M5-1；出口 1/2） |
| 二 | 同 impl 多实例共存（推荐不同 version，D6' 放开同版本）+ 绑定即实例 + 切换即时生效（事件失效）+ chainTrace + 回退 warn + 停用即回退（D-M5-2；出口 3） |
| 三 | 凭证函数唯一索引（落地或降级文档化）+ 压测冒烟 + call_log 零丢弃 + 全功能收口（D-M5-3；出口 4-7） |

## 已知边界（非缺陷）

- **压测绝对值不作 KPI**：开发库为远程 PolarDB（每 SQL WAN ~百毫秒），数字只做流程验证 + 相对基线（M4 实测 IN ~1s / OUT ~9ms 即为读放大佐证）；贴近生产需本地库复测。
- **绑定即实例（D6'）**：接口绑定时只选适配器实例（adapter_id），已无绑定版本下拉；binding.version 仅记录/留痕（若历史数据带 version 亦不影响运行时，恒用绑定行实例）。
- **回滚不覆盖适配器定义自身**（params/版本在适配器管理维度，回滚只恢复接口配置与绑定引用）。
- **status 流转（发布/下线）不生成版本**；创建即 v1.0 快照；删除接口级联删其全部快照。
