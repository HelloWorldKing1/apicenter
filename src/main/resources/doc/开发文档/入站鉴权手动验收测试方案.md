## 0. 准备：**先搞清怎么切模式**（本方案唯一的"非页面"操作）

鉴权是否强制由**平台级启动期属性** `app.api-center.client-auth.mode` 决定，**改后需重启后端**：

| 模式 | 含义 | 本方案用在 |
|---|---|---|
| `OFF` | **不校验**（现状；**仍写审计**，供观察期看清谁在调） | 阶段一 |
| `OPTIONAL` | 带凭证就严格校验、不带凭证放行（灰度观察） | 阶段二 |
| `ENFORCED` | 必须通过（**fail-closed**） | 阶段三 / 四 |

切换方式（任选其一，**都要重启后端**）：

- 改 `src/main/resources/application.yaml` 里的 `client-auth.mode` 后重启；或
- 启动参数覆盖：`--app.api-center.client-auth.mode=ENFORCED`

> **运行期可用的开关**（**无需重启**）：在「调用方管理」页**停用/启用单个调用方** —— 停用即拒（40107）。
> 这是应急回退的第一手段；整体回退才需要把 `mode` 改回 `OFF` 并重启。

**准备一个"被调的出站接口"**：任意一个已发布的**出站中转**接口即可（如 fastmoss 种子接口，或自己建一个指向
`https://earthquake.usgs.gov` 的 GET 接口），下文记作 **`<出站接口>`**。

- [ ] 后端/前端已启动；知道怎么改 `client-auth.mode` 并重启
- [ ] 已有一个**已发布**的出站中转接口可被调用

> 若开发库导入过种子（`POST /api/admin/seed/import`），会自带一个**演示调用方** `DEMO-CLIENT`
> （方式 = 调用方 API Key 验签，示例密钥 `demo-client-key-1234`）—— 阶段二可跳过"新建调用方"，直接用它。

## 阶段一 · 观察模式（`mode=OFF` + 审计）—— 约 3 分钟

> **为什么先跑这一阶段**：上强制之前必须先**看清谁在调**。`OFF` 不校验但**照常写审计**，
> 这是灰度上线纪律 S0 的核心（设计方案 §15）。

1. 确认 `client-auth.mode=OFF`（默认即 OFF）→ **重启后端**；
2. 用任意方式调一次 **`<出站接口>`**（例如在「接口管理 → 详情 → 测试接口」直接触发即可）；
3. 打开 **接口监控 → 「接入鉴权」Tab**：

- [ ] 摘要卡出现数字：**通过 +1**；「未识别主体」也为 `+1`（因为没带主体头）
- [ ] 表格首行：**方向 = 调用方**、**方式 = NONE**、**结果 = 通过**、**来源 IP = 本机 IP**、**主体 = 未识别**
- [ ] 说明列写着"OFF/OPTIONAL 且未带主体"之类的原因

> 📌 **这一阶段的意义**：`OFF` 下你看到的这张表，就是上线前判断"**哪些调用方还没带凭证**"的唯一依据 ——
> 灰度纪律要求**逐个调用方拿到"不带凭证的存量调用量 = 0"的证据**后才能进 `ENFORCED`（§15 硬要求）。

## 阶段二 · 配置调用方 + 灰度（`mode=OPTIONAL`）—— 约 8 分钟

### 2.1 建调用方与凭证（全程页面）

1. 侧边栏 **调用方管理**（图标 ◫）→ 「**＋ 新建调用方**」：

| 字段 | 填什么 |
|---|---|
| 调用方标识 | `PM-AUTH-CLIENT`（3~32 位大写字母/数字/`-`/`_`） |
| 名称 | `入站鉴权验收调用方` |
| 联系人 | 随意 |
| **鉴权适配器** | **调用方 API Key 验签** |
| IP 白名单 / 黑名单 | **都留空**（本阶段验"不限 IP"的情形） |
| QPS 上限 / 日调用量上限 | 留空或 `0`（**当前版本不生效**，列已预留） |
| 描述 | 随意 |

2. 保存后，列表该行点「**凭证**」→ 抽屉里类型选 **API Key** → 「**生成新凭证（平台随机）**」：

- [ ] 抽屉里出现一段**明文**，并提示"仅此一次" —— **复制保存它**（下文记作 `<密钥>`）
- [ ] 表格里新增一行：类型 = `API Key`、状态 = **ROTATING**、指纹 = 明文尾 4 位
- [ ] **明文不可再查**：关闭抽屉再打开，只剩 `****xxxx` 指纹（永不回显）
- [ ] 点该行「**激活**」→ 状态变 **ACTIVE**（此时该凭证才能真正用于鉴权）

> ⚠️ **ROTATING ≠ 已生效**：`ACTIVE` 才是"平台用作校验"的凭证；`ROTATING` 是"待激活/轮换并存"。
> 忘激活 = 阶段二带对头也会 401（错误码 `40100`），这是最常见的自坑。

### 2.2 切 `OPTIONAL` 并验证三种情形

把 `client-auth.mode=OPTIONAL` → **重启后端**，然后依次调 **`<出站接口>`**：

| # | 怎么调 | 预期 |
|---|---|---|
| ① | **带对头**：`X-Client-Id: PM-AUTH-CLIENT` + `X-Api-Key: <密钥>`（页面用「测试接口」不便带头时，用《使用教程》§9.1 的 curl；**本步是本方案唯一建议用 curl 的地方**） | `200`；「接入鉴权」新增 `通过 / API_KEY / 主体名=入站鉴权验收调用方 / 来源 IP` |
| ② | **带错密钥**（把 `<密钥>` 改一位） | `401`（`40100`）；审计 `拒绝 / 40100`，**主体名仍可读**（名称快照的意义） |
| ③ | **不带任何头** | `200`（OPTIONAL 放行）；审计 `通过 / NONE`（这就是灰度期"还没上车的调用方"） |

- [ ] ① 通过且审计三字段齐全（**主体名 · 来源 IP · 方式**）
- [ ] ② 被拒 40100，且**审计里能看到是谁**（不是"未知主体"）
- [ ] ③ 放行（OPTIONAL 的语义：不破坏尚未改造的调用方）

## 阶段三 · 强制与联动（`mode=ENFORCED`）—— 约 10 分钟

把 `client-auth.mode=ENFORCED` → **重启后端**。

| # | 操作 | 预期 |
|---|---|---|
| 1 | **裸调** `<出站接口>`（不带任何头） | `401`（`40107` 缺少主体标识头） |
| 2 | 紧接着看 **接口监控 → 「状态机与对账」** | **该次调用零新增**（拒绝发生在落运行表之前 ⇒ **不污染状态机**） |
| 3 | **带对头**调（`X-Client-Id` + `X-Api-Key`） | `200`；审计 `通过 / API_KEY` |
| 4 | 在「接入鉴权」Tab 点该行的 **`traceId`**（或按 traceId 到「调用日志」筛） | 能看到这次调用的 **IN/OUT 报文** —— **"谁调的" ↔ "调了什么"串起来** |
| 5 | 「接入鉴权」按 **结果 = 拒绝** 筛；再按 **来源 IP = 本机** 筛 | 筛选结果与上面一致（表格与摘要卡数字对得上） |
| 6 | 回「调用方管理」把 `PM-AUTH-CLIENT` **停用** → 再带对头调 | `401`（`40107` **调用方已停用**）；**无需重启**（运行期即时生效） |
| 7 | 再「启用」→ 带对头调 | `200` 恢复 |
| 8 | 新建 `PM-AUTH-NOADAPTER`（**鉴权适配器留空**）→ 带主体头调 | `401`（`40108` 未配置鉴权方式）—— **fail-closed，不会回退"无鉴权"放行** |
| 9 | 把 `PM-AUTH-CLIENT` 的 **IP 黑名单**填成本机 IP → 带对头调 | `401`（`40103` 来源 IP 被拒）；审计里 IP 可见 |
| 10 | 连续快速裸调 ≥10 次 | 「接口监控 → 告警」出现 **`auth_fail_streak`（CRITICAL）** 事件，文案含**主体/未识别主体 + IP** |

- [ ] 1~2 关键：`40107` 且**运行表零新增**
- [ ] 3~5 通过、串联、筛选三件事都对
- [ ] 6~7 停用/启用**即时生效**（运行期应急开关）
- [ ] 8 **fail-closed**（未配鉴权方式 = 拒，不是放行）
- [ ] 9 IP 维度生效且可归因
- [ ] 10 告警可触发（阈值默认 10 次 / 5 分钟窗口，`client-auth.fail-alert-threshold` 可调）

## 阶段四 · 回调侧与平台自调（`mode` 保持 `ENFORCED`）—— 约 4 分钟

| # | 操作 | 预期 |
|---|---|---|
| 1 | 用 curl 打一个 **入站回调接口**的平台路径（**故意发错签名**，正确签名见《使用教程》§9.2） | `401`（`40100`） |
| 2 | 看「接入鉴权」Tab | 出现一行：**方向 = 回调**、主体 = **供应商**（应用名）、**方式 = HMAC-SHA256**、结果 = 拒绝、错误码 `40100` |
| 3 | **关键回归（D-CA-17）**：在「接口管理」里对一个**入站回调接口**点「**模拟回调**」 | **仍能正常工作**（不应被鉴权拦住）—— 审计里出现 **方式 = PLATFORM_SELF** 的行 |

- [ ] 1~2 回调方向的判定也留痕（`direction=CALLBACK`，主体是供应商、不是调用方）
- [ ] 3 **平台自调不被自家闸门打死** —— **这一条失败 = `ENFORCED` 一上线，「模拟回调」这个调试工具会直接失效**

> 为什么单列第 3 条：「模拟回调」是**自调网关**（`POST http://localhost:{port}{平台侧路径}`），
> 它同样会经过鉴权闸门。平台为此内置了**内部调用令牌**豁免（`X-Internal-Token`，仅内存、常量时间比较、
> 空令牌不放行），审计记为 `PLATFORM_SELF` 以便与真实外部调用区分。

## 5. 常见误判（**先看这张表再报缺陷**）

| 页面上的现象 | 是不是缺陷 | 说明 |
|---|---|---|
| 改了 `client-auth.mode` 但行为没变 | ❌ 不是 | 它是**启动期属性**，**必须重启后端**（单调用方的停用/启用则无需重启） |
| `OFF` 下「接入鉴权」里就有记录 | ❌ 不是 | **有意**：`OFF` 仍写审计，用于观察期盘点存量调用方（§15 S0） |
| 凭证生成了，但带对头仍 `40100` | ❌ 不是 | 新凭证是 **ROTATING（待激活）**，要先点「激活」变 `ACTIVE` |
| `ENFORCED` 下报 `40108` 而不是 `40100` | ❌ 不是 | 该调用方**没配鉴权方式**（或适配器已停用）—— **fail-closed**，不会回退 Noop |
| 报 `40107` 但调用方明明存在 | ❌ 不是 | 调用方被**停用**了；或头名不是 `X-Client-Id`（可在适配器 params 里改名） |
| 审计表里刚发生的调用"查不到" | ❌ 不是 | 审计是**异步批量写**（攒 50 条或 1 秒），**最多延迟约 1 秒**；刷新即可 |
| 用 `127.0.0.1` 与 `localhost` 打开前端，行为不一致 | ❌ 不是 | CORS 按 Origin 放行（两者不同源）；见《使用教程》FAQ Q0 |
| 平台自己的「模拟回调」被拒 | ✅ **是缺陷** | 内部令牌豁免没生效（D-CA-17）—— 报缺陷 |
| 带对头但报 `401`，`msg` 说 `X-Client-Id` 相关 | ❌ 不是 | 先核对**头名大小写与拼写**、再核对调用方标识是否为**大写**（标识格式校验 3~32 位大写） |
| 配额（QPS / 日调用量）填了没生效 | ❌ 不是 | **本版本不生效**（列已预留，P2）；当前只有 IP 名单与鉴权生效 |

## 6. 灰度操作手册（上线纪律，照设计方案 §15）

| 步骤 | 配置 | 观察什么 | 通过标准 | 回退 |
|---|---|---|---|---|
| **S0 部署（不改行为）** | `mode=OFF` | 「接入鉴权」Tab：谁在调、用什么方式、IP 分布、**未带主体的量** | 「不带任何凭证头」的合法调用方清单已明确 | 停写审计即可（改回默认） |
| **S1 配置调用方** | 仍 `OFF` | 给每个调用方建 `client_app` + 适配器 + 凭证，并**书面通知**其改造（加 `X-Client-Id` + 密钥） | 逐个调用方**在他们那边**改完并验证通过（审计 `PASS / API_KEY`） | 删调用方 |
| **S2 灰度** | `OPTIONAL` | 拒绝数应 ≈ 0（或全是**配置错**的调用方）；「带主体但无凭证」的量 | **连续 1 天拒绝率 ≈ 0** | `OFF` |
| **S3 强制** | `ENFORCED` | 拒绝数、未识别主体、`auth_fail_streak` 告警 | 拒绝**仅**来自预期外来源 | `OPTIONAL` → `OFF` |
| **S4 收尾** | 保持 `ENFORCED` | —— | 通知/文档已更新（调用方知道要带什么头） | —— |

> ⚠️ **两条硬要求**：① **禁止**跳过 S0/S2 直接 `ENFORCED`；
> ② 进 `ENFORCED` 前必须**逐个调用方**拿到「**不带凭证的存量调用量 = 0**」的审计证据。

## 7. 收尾与回归

1. **回退模式**：把 `client-auth.mode` 改回 `OFF` 并重启（**否则后续测试/联调都会被鉴权拦住**）；
2. **删除验收造数**：调用方管理里删 `PM-AUTH-CLIENT` / `PM-AUTH-NOADAPTER`（凭证级联删，**审计保留**）；
3. **审计表**按保留期自行清理（默认 90 天；P1 手工，`DELETE FROM access_auth_log WHERE created_at < …`）；
4. **回归**：`cd frontend && npm test`（单测 + SSR）、后端 `mvn -o clean test`（全量；⚠️ 必须 `clean`）。

> 本方案**不产生**状态机/死信类残留（鉴权拒绝**不落运行表**）—— 这正是"拒绝不污染状态机"的直接体现。
