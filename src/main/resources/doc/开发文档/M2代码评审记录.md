## 一、问题清单（合并去重，按严重度）

### 高危（建议立即处理）

| # | 位置 | 问题 |
|---|---|---|
| 1 | `mapping/MappingEngine` | **condition 操作未先求值**：引擎把「source 为 null → 直接 null 策略」对全部 op 前置；M0-02 §4.5 语义是 condition **先求值**——false → 跳过且不触发 null 策略（矩阵 #20：null 输入 + ERROR 不应报错）。现状 source null + 条件为假时 ERROR 误抛 40001、KEEP 误写 null |
| 2 | `OutboundEngine.replay` / `worker/CompensationWorker` | **补偿重放遇超时/连接异常无归类**：replay 只 catch BizException，`ResourceAccessException` 穿透 worker 批次（单行异常中断整批），记录悬浮 COMPENSATING——不转 UNKNOWN 也不重试；补偿重放恰是最可能超时的场景。且首送与重放两路分类逻辑重复、易分叉 |
| 3 | `InterfaceService.delete` | **删接口的运行数据守卫只有注释没实现**：M2 已产生 outbound_request 运行数据，硬删接口会把运行表留成悬空 interface_id（无外键不报错），与 schema / M1 设计「存在运行数据仅允许下线」相悖 |

### 中危（本里程碑内应处理）

| # | 位置 | 问题 |
|---|---|---|
| 4 | `service/AdapterService` | **D6「同 impl 至多 1 条 enabled」漏检两条路径**：update 不校验 enabled 上限；create 不传 enabled 时（toRow 默认 true）整段跳过校验 |
| 5 | `service/CredentialService` | **并发下 (app_id, kind) 可出现 2 条 ACTIVE / 2 条 ROTATING**：约束仅应用层前置查询，库无兜底（非唯一索引）；并发 prepare/activate 可双写。建议 CAS 式 `UPDATE ... WHERE status='ROTATING'` 判受影响行数 |
| 6 | `JsonProtocolAdapter` / `OutboundEngine` 响应解析 | **超 long 大整数静默截断**：`isIntegralNumber → longValue()` 对 BigInteger 丢精度，违反 M0-01 §1「超出 long 范围 → DECIMAL」 |
| 7 | `InterfaceService.validate` | **callback_url / upstream_path 无格式校验**（仅非空）：入站回调地址应限 `https?://`，出站路径应拒绝对 URL / `..`，防错配与 SSRF 面 |
| 8 | 前端 `views/Apps.vue` | **凭证更新/重置写死 `kind:'OUTBOUND'`**：回调验签凭证在应用详情里无法更新（应带行 kind 操作） |
| 9 | 前端 `views/Interfaces.vue` | **onTypeChange 未清理 mappings / outParams 等残留**：出站→入站切换后旧映射语义可能错提交（后端提交时才报错，前端无行级指引；原型有逐行校验） |
| 10 | 前端列表页（Interfaces / Apps） | **搜索无防抖**：逐字符发请求，Interfaces.load 还顺带拉 apps/groups/adapters 三个字典；openEdit/openDetail 无独立 loading |
