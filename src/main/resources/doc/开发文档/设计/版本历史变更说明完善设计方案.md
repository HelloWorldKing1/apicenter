# 版本历史 · 变更说明完善设计方案

> 版本：v0.1（2026-09-07 已按拍板落地，待全量测试验证）｜范围：interface_snapshot.change_note 语义与展示增强（后端生成器 + 快照表结构 + 前端版本历史弹窗）
> **落地状态**：P1②（change_note 扩 VARCHAR(1000) + change_detail LONGTEXT，已 ALTER 并同步 schema）；P2 主字段+子表摘要；P3 ｜备注：组合；P4 回滚摘要极简「回滚至 v{目标}」、确认弹窗不收集 operator/reason；change_detail 生成 type=ROLLBACK（相对回滚前版本的字段差异），回滚行「变更详情」可用；P5 创建写「初始创建」；P6 已实现（旧配置 = 上一个快照，无额外读）。新增 SnapshotChangeDiff（含单测），M5IntegrationTest 回滚断言已同步。
> 事实基准：change_note 现为 VARCHAR(255) 自由文本，来源 4 类——① 创建 v1.0（空）② 编辑保存（`X-Change-Note` 头，可空）③ 回滚（自动拼「回滚至 v{目标}（operator=…, reason=…）」）④ 复制（自动拼「复制自 {源}#v{版本}」）。
> 现状痛点：② 多数用户留空 → 版本历史只有「v1.0 → v1.1」没有"改了什么"；③ 回滚说明携带 operator/reason 等过程信息，想看字段级差异只能逐条「快照」比对两段 JSON。

## 1. 目标

1. **每次配置变更自动生成简洁结构化变更说明**：主字段级给出 `字段：旧值 → 新值`；子表给出可读摘要（数量变化 / 新增删除 / 绑定切换等）；
2. **回滚说明极简**：只写 `回滚至 v{目标}`——不携带 operator / reason，不做「从 vX」补全；
3. 用户手填的 `X-Change-Note` 语义调整为「**备注**」：自动说明 + `｜备注：xxx` 组合展示（可空，不自动加）；
4. 前端版本历史弹窗支持**查看字段级变更详情**（old → new 表格/树），不再靠肉眼比 JSON。

## 2. 示例（目标态展示效果）

```
v1.2 ｜ 回滚至 v1.0
v1.1 ｜ 变更：读超时 3000→5000；入站参数 +1（order_state）｜备注：放宽超时
      └ [详情] 字段级变更：读超时(ms) 3000→5000 …（结构化展示）
v1.0 ｜ 初始创建（或「复制自 IF-FM-001#v1.1」）
```

## 3. 需求拆解

| 操作 | 自动生成内容 | 手填备注 | 详细结构 |
|---|---|---|---|
| 创建 | `初始创建`（或复制：`复制自 {源}#v{源版本}`） | 无 | type=CREATE / COPY（含源标识） |
| 编辑保存 | `变更：{摘要}`（主字段 + 子表摘要，最多 ~3 类） | `｜备注：{X-Change-Note}`（可空） | type=UPDATE + diff[]（见 §4） |
| 回滚 | `回滚至 v{目标}` | 无 | type=ROLLBACK + diff[]（回滚前当前配置 vs 目标版本） |
| 复制 | `复制自 {源code}#v{源版本}` | 无 | type=COPY + 源信息 |

> 说明：**所有操作文案都不再携带 operator / reason 等过程信息**（如需操作留痕，另行以审计能力承接）；回滚摘要不输出 `变更：` 文案（避免与目标版本内容混淆），但 change_detail 提供相对回滚前版本的差异供「变更详情」查看。

## 4. 变更差异生成器（ChangeNoteBuilder）

### 4.1 diff 源与时机（关键实现选择）
- **以快照 JSON 为统一 diff 源**：编辑保存时，在 `InterfaceService.update` **做任何 DB 变更前**先读取旧配置并序列化为 `oldJson`（复用一个新方法 `snapshotOf(InterfaceRow + 六段 Rows)`，与 `SnapshotSerializer.toJson` 同源）；再对本次 `InterfaceRequest` 归一化（复用 toRow/子表行映射）得 `newJson`；两段 JSON 交给差异引擎做 **key-path 叶子级 diff**。
- 好处：自动覆盖全部字段与子表行，不会漏字段；Serializer 已是回滚/复制的既成真相源，说明与可重建快照天然一致。
- 开销：保存路径增加一次旧配置读取（约 6 条子表 SELECT），管理面低频可接受（拍板 P6）。

### 4.2 diff 引擎输出（中间结构）
```jsonc
{
  "type": "UPDATE",
  "fields": [                       // 主字段叶子差异（label 中文化见 4.3）
    { "field": "timeoutMs", "label": "读超时(ms)", "old": "3000", "new": "5000" }
  ],
  "params":   [ { "action": "ADD", "key": "IN/order_state", "type": "string" } ],   // 入站/出站参数
  "mappings": { "count": "3→4", "changed": 1, "top": [ "第4条 rename order_state param null→PAID→已支付" ] },
  "fieldDefs":[ { "action": "DEL", "key": "RESP/ts" } ],
  "bindings": [ { "role": "MESSAGE", "old": "ADP-ENV-1:9.1", "new": "ADP-ENV-2:9.2" } ],
  "bodies":   [ { "side": "IN", "bodyType": "json→xml" } ],                        // raw 正文只记 hasChanged=true
  "manual": "放宽超时"             // X-Change-Note 备注原样
}
```
- 归并规则：主字段以 key 精确比较（`protocolIn/protocolOut/upstreamPath/callbackUrl/appId/groupId/status 不参与——status 由生命周期管理`）；`desc` 变更只在非空变化时记；数组类以 (side,name)/(role)/(kind,name) 为键做增删改三态。
- raw 长文（body.raw / 大 JSON）仅输出 `hasChanged: true`，不落全文，防爆库。
- 空差异（仅备注）：摘要=「无字段变化（仅备注）」；完全无差异且无备注：摘要=「配置变更（无字段变化）」（罕见，乐观锁自增仍会落一版）。

### 4.3 中文 label 映射
| key | label | | key | label |
|---|---|---|---|---|
| name | 名称 | | maxRetries | 最大重试 |
| path | 平台侧路径 | | desc | 描述 |
| upstreamPath | 供应商接口路径 | | protocolIn/Out | 入站/出站协议 |
| callbackUrl | 回调地址 | | appId | 归属应用 |
| groupId | 分组 | | timeoutMs | 读超时(ms) |
| params | 请求参数 | | bodies | Body |
| mappings | 字段映射 | | bindings | 适配器绑定 |
| fieldDefs | 响应/ack 字段 | | method | HTTP 方法 |

### 4.4 摘要文本压缩规则
- 主字段最多列 3 条 +「等 N 项」；子表每类 ≤2 条，超限省略；总体 ≤ 200 字符（手填备注独立 ≤250 后拼装，DB 列已扩至 1000，见 §6）；
- 摘要前缀统一为 `变更：`（编辑保存）与动作词（`回滚至` / `初始创建` / `复制自`）——不加编号、时间、操作人或原因。

## 5. 存储与展示方案（拍板 P1）

| 方案 | 存储 | 前端展示 | 取舍 |
|---|---|---|---|
| ① 单列纯文本 | `change_note` 扩 VARCHAR(1000)，存摘要文本（组合备注） | 版本历史列直接展示文本 | 改动最小、历史语义不变；但字段级 old→new 只能看文本，无法按结构渲染/检索 |
| **② 摘要文本 + 结构化列（推荐）** | `change_note` 存摘要文本（含组合备注，扩 VARCHAR(1000)）+ 新增 `change_detail` LONGTEXT（JSON，机器可读） | 列展示摘要；行操作「详情」→ 结构化渲染（主字段表格 + 子表变更块，old→new） | 兼顾可读与结构化；老数据 detail 为空时降级为纯文本 |
| ③ 仅 JSON 列 | 只存 change_detail JSON，前端本地渲染摘要 | 每次渲染现算摘要 | 列最少，但列表/详情都依赖解析渲染，简单展示场景多一层 |

## 6. 兼容与迁移
- `change_note VARCHAR(255) → VARCHAR(1000)`（四类来源合并摘要长度仍可能逼近）；新增 `change_detail LONGTEXT NULL`；
- ALTER 开发库 + schema.sql / 表结构设计.html 同步；rollback/复制生成器一并入新格式；
- **老数据**：change_detail=NULL → 前端“详情”按钮置灰/显示“历史记录无结构化详情”，change_note 原样展示；
- 现有断言/文档校准：M5IntegrationTest（latestChangeNote 断言改为简洁文案，如含「回滚至 v1.0」；X-Change-Note 备注用例调整）、M5 开发计划/手动验收/整体测试方案中 change_note 文案示例；限长校验（H2，≤250）保留给手填备注，生成摘要由引擎内截断。

## 7. 前端改动（方案②）
- 版本历史表格「变更说明」列：文本 ellipsis + tooltip；
- 行「详情」按钮（change_detail 非空）→ 弹窗：
  - 主字段表格（label/旧值/新值）；
  - 子表变更块：params 增删（新行绿色/删除行红色样式可简化为文字前缀）、mappings 变更 top 列表、bindings `role: 旧 → 新`；
  - 摘要 + 手填备注区；
- 「快照 JSON」按钮保留（仍可查看可重建快照原文）；
- 编辑弹窗 `X-Change-Note` 输入 label 与 placeholder 改为“备注（可选，追加到自动生成变更说明）”。
