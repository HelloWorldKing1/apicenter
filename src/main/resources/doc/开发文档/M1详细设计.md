### 2.2 统一响应信封与错误码

```json
{ "code": 0, "msg": "ok", "data": {} }
```

M1 用到的错误码（设计 §6.2 全集中的子集）：40100 验签失败、40102 应用未启用、40001 字段缺失、40002 报文格式非法、40401 接口不存在、40402 应用不存在、50000 未知异常。新增业务校验错误统一归入 40001（msg 指明具体校验失败原因）。

### 2.3 管理面 REST API 面

前缀统一 `/api/admin`（执行面 M2 起用 `/api` 路由 + `/callback`，互不冲突）。

**应用**：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/apps?keyword=` | 列表（含分组数 / 接口数） |
| GET | `/api/admin/apps/{appId}` | 详情（含凭证遮显列表） |
| POST | `/api/admin/apps` | 创建（状态 DRAFT；校验 appId 唯一） |
| PUT | `/api/admin/apps/{appId}` | 编辑（名称 / 联系人 / 服务地址 / 黑白名单 / 配额 / 默认适配器） |
| POST | `/api/admin/apps/{appId}/enable` | 启用（仅 DRAFT / DISABLED） |
| POST | `/api/admin/apps/{appId}/disable` | 停用（仅 ENABLED） |
| POST | `/api/admin/apps/{appId}/cancel` | 注销（仅 DISABLED；注销后 appId 不回收，状态终态） |
| DELETE | `/api/admin/apps/{appId}` | 删除（存在接口 → 40001 拒绝；级联删分组与凭证） |

**分组**：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/groups?appId=` | 两级视图（按应用组织的树形） |
| POST | `/api/admin/groups` | 创建（校验组属于所选应用；应用内组名唯一） |
| PUT | `/api/admin/groups/{id}` | 编辑（名称 / 排序） |
| DELETE | `/api/admin/groups/{id}` | 删除（**组下有接口 → 40001 拒绝**，引导先移走接口） |

**接口**：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/interfaces?appId=&groupId=` | 列表 |
| GET | `/api/admin/interfaces/{id}` | 详情（含 param / body / field_mapping / field_def / binding 子表） |
| POST | `/api/admin/interfaces` | 创建（事务：主表 + 子表；类型互斥校验；code / path 全局唯一） |
| PUT | `/api/admin/interfaces/{id}` | 全量更新（事务：主表 + 子表删了重建；**version 乐观锁**——请求带当前 version，匹配才更新并自增，不匹配返回 409 冲突） |
| POST | `/api/admin/interfaces/{id}/publish` | 发布（仅 DRAFT / OFFLINE） |
| POST | `/api/admin/interfaces/{id}/offline` | 下线（仅 PUBLISHED） |
| DELETE | `/api/admin/interfaces/{id}` | 删除（级联删 6 子表；存在运行数据仅允许下线——M1 无运行数据，校验逻辑预留） |

**适配器注册表**：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/adapters?type=` | 列表 |
| GET | `/api/admin/adapters/impls` | impl 元数据清单（名称 + 参数 schema，前端动态渲染表单） |
| POST | `/api/admin/adapters` | 创建（params 按 impl schema 校验；同 impl 至多 1 条 enabled=1，M0-01 D6） |
| PUT | `/api/admin/adapters/{id}` | 编辑 |
| POST | `/api/admin/adapters/{id}/enable` / `.../disable` | 启停 |
| DELETE | `/api/admin/adapters/{id}` | 删除（引用列置 NULL：app 三列 + binding.adapter_id，schema 删除策略） |

**凭证**：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/apps/{appId}/credentials` | 列表（遮显：kind / status / 尾 4 位指纹 / 生效与失效时间，**永不回显明文**） |
| POST | `/api/admin/apps/{appId}/credentials/prepare` | 生成新凭证 `status=ROTATING`（出站轮换第一步：等供应商侧配置） |
| POST | `/api/admin/apps/{appId}/credentials/{id}/activate` | 激活：新 → ACTIVE、旧 ACTIVE → ROTATING（rotating_until=+24h）（M0-04 流程①） |
| POST | `/api/admin/apps/{appId}/credentials/update` | 一步更新（供应商主动轮换回调密钥场景）：新 → ACTIVE、旧 → ROTATING（M0-04 流程②） |
| POST | `/api/admin/apps/{appId}/credentials/{id}/retire` | 立即失效 → RETIRED（泄漏应急；ACTIVE 被失效且无替代时告警提示，M0-04 流程④） |
| POST | `/api/admin/apps/{appId}/credentials/{id}/finish-rotation` | 完成轮换：ROTATING → RETIRED（提前收尾） |
| POST | `/api/admin/apps/{appId}/credentials/reset` | 重置：新 → ACTIVE、旧全部 → RETIRED（M0-04 流程③） |

### 2.4 生命周期状态机（应用 / 接口）

- **应用**：`DRAFT → ENABLED → DISABLED → CANCELLED`（终态 CANCELLED）。流转走操作端点，拒绝非法流转（如 ENABLED 直接 cancel → 40001）。
- **接口**：`DRAFT → PUBLISHED → OFFLINE`（OFFLINE 可回 PUBLISHED）。
- **「停用即拒请求」钩子**：M1 无执行面，钩子为 `AppService.isRequestAllowed(appId)` 方法 + 单测（状态非 ENABLED 一律拒绝）；M2 接入层路由时调用（M1 测试点的网关校验部分 M2 闭环）。

### 2.5 接口类型互斥校验（M1 核心校验，对照开发计划测试点）

| 校验 | OUTBOUND 出站 | INBOUND 入站 |
|---|---|---|
| 目标地址 | `upstream_path` 必填；`callback_url` 必须为空 | `callback_url` 必填（URL 格式校验）；`upstream_path` 必须为空 |
| 字段定义 kind | 仅允许 RESP（ack 字段清空） | 仅允许 ACK（响应字段清空） |
| 出站侧送达报文 | 出站侧（side=OUT）参数 / Body 可选 | **出站侧（side=OUT）参数 / Body 必填**（= 送达报文，设计 §3.1） |
| 适配器绑定角色 | 仅 MESSAGE / AUTH | 仅 MESSAGE / CALLBACK_AUTH |
| 字段映射校验 | target 必填；非 default 需 source；参数化操作需 param（M0-02 校验规则） | 同左 |

- **两级下拉**：新建接口先选应用、再选该应用下的分组；`group_id` 必须属于所选应用（服务端校验，前端联动）。
- 接口 `code` / `path` 全局唯一（uk 约束 + 服务端预校验给出友好错误）。

### 2.6 凭证组件（CryptoService + CredentialService）

- **加密**：AES-256-GCM 可逆加密（M0-04 §3.4）。密文格式 `base64(iv ‖ ciphertext ‖ tag)`。密钥来源：`app.api-center.crypto.key`（base64 编码 32 字节；开发环境配置在 application.yaml 本地段，生产走环境变量 `APICENTER_CRYPTO_KEY`，配置缺省时**启动失败**并提示——禁止明文裸跑）。
- **指纹**：回显尾 4 位（`credential.substring(len-4)`，解密后计算），列表 / 详情遮显。
- **状态机约束**（M0-04 §3.1）：每 (app_id, kind) 的 ACTIVE 至多 1、ROTATING 至多 1；activate 必须存在对应 ROTATING；retire 后无 ACTIVE 时接口返回告警标记。
- **入库断言**：库中 `credential` 列不得出现明文（单测扫描断言）。

### 2.7 适配器注册表骨架（M1 只做定义与校验，M2 执行）

- `impl` 元数据清单（后端常量表，M1 硬编码，M2 与 Bean 注册打通）：首期 6 鉴权（Noop / ApiKey / Hmac / BearerToken / CloudSignature / CloudCallbackSignature）+ 2 协议（Json / Xml）+ 3 报文（NoopMessage / Envelope / HeaderMapping），参数 schema 照原型 ADAPTER_FIELDS（M0-01 §8 清单）。
- `params` 校验：按 impl schema 校验必填 / 类型 / 枚举取值；凭证类参数拒绝写入（提示存凭证走凭证管理）。
- 预置数据：平台默认实例 NoopAuthAdapter / NoopMessageAdapter 在种子中落库（M0-01 D4 平台默认兜底的实现载体）。

## 3. 持久化约定

- 无 JPA：JdbcTemplate + 手写 RowMapper；实体为 `record`。
- `interface` 创建 / 更新为**单事务**（主表 + param/body/mapping/field_def/binding 子表；更新 = 子表 DELETE + 重建，全量语义）。
- **更新策略定稿（评审确认点 5）**：全量替换 + `interface.version` 乐观锁。选全量而非 diff 的理由：① 子表 id 无外部引用（snapshot 是 JSON 快照、运行表只引用 interface_id）；② mapping 表无自然 key，diff 逻辑复杂无收益；③ 配置低写频，重写无压力。version 从 M1 起做乐观锁（PUT 校验一致后自增），M5 版本化只需在自增时写 snapshot。
- 时间字段用数据库默认值（CURRENT_TIMESTAMP），代码不塞时间。
- 命名：SQL 全小写蛇形，列名与 schema.sql 一致。

## 4. 前端设计（管理面框架）

**评审定稿：Vue3 + Vite + Element Plus（方案 B）**。工程组织：

- **目录**：`frontend/`（独立 Vite 工程，与后端同仓库）；构建产物输出到 `src/main/resources/static/`（Spring Boot 直接 serve）。
- **语言**：JavaScript（与原型一致，1524 行交互逻辑平移直接复用，不引入 TS 转换成本；后续如需 TS 可再迁移）。
- **依赖**：Vue 3、Vite、Element Plus（表格 / 表单 / 弹窗 / 树 / 下拉）、Axios（统一封装 `/api/admin` 前缀 + 统一信封解包 + 错误提示）。
- **开发联调**：Vite dev server（5173）+ proxy `/api` → `localhost:8080`；后端 WebConfig 保留 CORS 兜底。
- **页面**（原型交互平移，数据源改为后端 API）：
  - 布局：侧边导航（概览 / 应用 / 分组 / 接口 / 适配器 / 监控）+ 面包屑（照原型）；
  - 应用页：列表 + 新建 / 编辑弹窗 + 详情（凭证遮显区 + 轮换操作按钮）+ 生命周期操作（启用 / 停用 / 注销）；
  - 分组页：应用 → 分组树（两级视图）+ 增删改；
  - 接口页：列表 + 大弹窗（基础 / 协议 / 归属两级下拉 / 目标 / 超时重试 / 入站出站参数与 Body 双 tab / 字段映射表格（6 操作动态 param 输入）/ 响应·ack 字段 / 适配器绑定），类型联动（OUTBOUND vs INBOUND 字段切换照原型 onIfTypeChange）；
  - 适配器页：三类 tab 过滤 + 列表 + 参数动态表单（接 `/adapters/impls` 元数据渲染）+ 启停；
  - 监控页：原型静态数据保留（M4 接真实）。
- **验收标准**：黄金用例配置（fastmoss 应用 / 凭证 / 接口 / 参数 / 响应字段 / 绑定）全程通过前端操作完成并回读一致。

## 5. 种子数据（fastmoss 黄金用例）

- **载体**：`SeedDataInitializer`（ApplicationRunner，幂等：检测 `app` 表已有 `app_id='fastmoss'` 则跳过，可配 `app.api-center.seed.enabled` 默认 true）。
- **内容**（对照开发计划 §2.2）：
  - 应用 fastmoss（ENABLED，base_url=https://openapi.fastmoss.com，auth_adapter_id=Bearer 实例）；
  - 凭证：kind=OUTBOUND，测试 token 经 **CryptoService 运行时加密**落库（种子 SQL 无法预加密——密钥在运行时，这是选 Runner 而非纯 SQL 的原因）；
  - 适配器：Bearer Token 实例（headerName=Authorization / prefix=Bearer）、EnvelopeMessageAdapter（envelope=data / codeField=code / successValue=0 / messageField=message）、NoopAuth / NoopMessage 平台默认；
  - 接口 IF-FM-001（OUTBOUND、POST、/fastmoss/creatorList、JSON/JSON、upstream_path=/shop/v1/creatorList、PUBLISHED）+ 入站参数 4 个（filter.seller_id / orderby / page / pagesize，Body=json）+ 出站参数同（透传）+ 出站响应字段（total / list）+ 绑定（AUTH=Bearer、MESSAGE=Envelope）；
  - 分组「默认分组」。
- 原型 demo 数据（腾讯云 / 智慧芽示例）**默认不导入**（避免与真实配置混淆），原型 HTML 自带静态演示数据。
