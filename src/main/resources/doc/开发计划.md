## 2. 第一个可演示版本（黄金用例）

> M2 的出口标准由本用例定义：把下面这条真实调用跑通（配置 → 调用 → 断言），即为第一个可演示版本。

### 2.1 目标与范围

- 协议：**JSON-JSON**；只覆盖出站中转链路——入站回调、XML、字段映射不在本用例内（映射能力由 M2 单测矩阵验收，本用例聚焦「链 + 鉴权 + 信封」）。
- 鉴权：**Bearer Token**（`Authorization: Bearer <token>`，token 为测试值）。
- 调用方鉴权：平台统一处理（范围外），本用例调用方不验签。

### 2.2 配置数据（种子）

| 配置 | 值 |
|---|---|
| 应用 app | app_id=`fastmoss`，name=FastMoss，base_url=`https://openapi.fastmoss.com`，auth_adapter_id=Bearer Token 鉴权实例（只配 headerName=Authorization / prefix=Bearer），callback_auth_adapter_id=NULL，status=ENABLED；**凭证 app_credential：kind=OUTBOUND，credential=测试 token**（Bearer 凭证，AES-256-GCM 加密存储，status=ACTIVE） |
| 接口 interface | code=`IF-FM-001`，if_type=OUTBOUND，method=POST，path=`/fastmoss/creatorList`，protocol_in=protocol_out=JSON，upstream_path=`/shop/v1/creatorList` |
| 入站侧参数（IN） | filter.seller_id(string, 必填)、orderby(array)、page(number)、pagesize(number)；Body=json（模板见 2.4） |
| 出站侧参数（OUT） | 与入站侧一致（**透传**） |
| 字段映射 | 空（纯透传） |
| 出站响应字段（RESP） | total(number)、list(array，元素字段见响应样例) |
| 适配器绑定 | AUTH=Bearer Token 适配器；MESSAGE=EnvelopeMessageAdapter（envelope=`data` / codeField=`code` / successValue=`0` / messageField=`message`）；协议适配器按 JSON 自动推导 |

### 2.3 验收断言（黄金用例）

| # | 场景 | 预期 |
|---|---|---|
| G1 | 正常调用（请求体见 2.4） | HTTP 200；平台统一信封 `code=0`、`msg=""`、`data.total=822`、`data.list[0].nickname="megan!"`、`data.list[0].units_sold=1135`；出站状态机落 SUCCESS |
| G2 | Bearer token 缺失 / 错误 | 上游 401（4xx）→ 写死信、出站状态 DEAD_LETTER，平台返回失败 + deadLetterId |
| G3 | 上游 5xx / 429 | @Retryable 短重试（指数退避）；耗尽 → COMPENSATING，补偿 worker 兜底 |
| G4 | 上游超时 | UNKNOWN → 对账分支 |

## 3. 里程碑明细

### M0 设计定稿（3 人日）

| 任务 | 人日 |
|---|---|
| 链引擎契约设计：Adapter 接口（type/order/supports/process）、AdapterContext、链编排、绑定继承 / 覆盖解析、协议自动推导规则 | 1 |
| 动态映射规则语义规范：6 操作 × param 语法、类型注册表边界行为（number→DATE 等定死）、condition 表达式沙箱约束 | 1 |
| 通用声明式客户端约定（按协议维度接口 + 动态 URI / 凭证组装）+ UNKNOWN 对账查询协议与兜底策略 | 1 |

**测试点**：契约设计评审通过（评审记录）；映射语义规范覆盖 6 操作 × 4 空值策略全部组合的预期输出定义。

### M1 骨架（8 人日）

| 任务 | 人日 |
|---|---|
| 管理面框架（原型交互平移）+ 导航 / 弹窗 / 表单组件 | 2 |
| app / app_group / interface CRUD + 生命周期状态机 + 两级下拉 + 类型互斥校验 | 3 |
| 凭证管理（app_credential 表：加密存储 / 遮显回显 / 轮换并存 / 重置 / 即时失效，见 M0-04）+ 适配器注册表骨架 | 2 |
| schema.sql 落库 + 初始化数据（fastmoss 黄金用例配置为首个种子，见第 2 节；原型 demo 数据可保留） | 1 |

**测试点**：
- 单测：应用生命周期流转（草稿→启用→停用→注销，停用即拒请求）；接口类型互斥（OUTBOUND 禁 callback_url / ack 字段，INBOUND 必填回调地址与出站侧送达报文）；凭证加密落库 + 界面遮显；分组归属校验（组必须属于所选应用）
- 集成：16 张表 DDL 可重复执行；配置 CRUD 全链路；黄金用例配置可入库并回读校验（应用 / 接口 / 参数 / 响应字段 / 绑定）

### M2 出站链路（15 人日）—— 难度峰值

| 任务 | 人日 |
|---|---|
| 适配器链引擎（契约 + Context + 链组装 + 绑定解析 / 继承覆盖 + 灰度索引） | 5 |
| 动态字段映射引擎（6 操作 + param + 表达式沙箱 + 类型注册表） | 5 |
| 通用声明式客户端（动态 URI / 凭证组装 + 连接池）+ JSON 编解码（每应用独立实例） | 2 |
| 出站状态机 + @Retryable Invoker（熔断闸门前置）+ 补偿 worker + 死信 + **黄金用例端到端调通** | 3 |

**测试点**：
- 单测：映射 **6 操作 × 4 空值策略矩阵（≥24 例）**；状态机每条边（成功 / 4xx 死信 / 5xx 重试 / 重试耗尽补偿 / 超时 UNKNOWN）；绑定解析（继承 / 覆盖 / 协议自动推导）；**表达式注入用例（沙箱拦截）**；类型转换边界
- 集成：outbox 先记后发；补偿 worker 按 (status, next_retry_at) 扫描重试；死信落库 + 重放；QPS 限流 / 配额拒绝不污染状态机
- **黄金用例（第 2 节）**：G1 成功路径断言（code=0 / total=822 / nickname="megan!"）；G2 无 / 错 token → 上游 401 → 死信分支；G3 上游 5xx/429 → 重试 / 补偿分支；G4 超时 → UNKNOWN 对账分支

### M3 协议与入站（12 人日）

> **状态：已完成（2026-09-03，全库 103 测试全绿）**。细分计划与设计定稿见 `doc/开发文档/M3开发计划.md`（D-M3-1~4 为编码依据，经七轮评审；含手动验收方案）。

| 任务 | 人日 |
|---|---|
| XML 编解码（根元素 / 命名空间 / 属性映射 / 空值策略） | 2 |
| 入站回调链路：回调验签 → 映射 → 送达（回调地址快照）→ ack 回执 → 补偿重送 | 6 |
| 出站响应字段 / ack 回执字段解析 | 2 |
| 四种转换场景补全（json-xml / xml-xml / xml-json） | 2 |

**测试点**：
- 单测：XML 边界（空值 / 命名空间 / 属性）；回调验签失败 401 且不落送达记录；**ack 回执与送达解耦（送达失败仍回 ack，供应商不重发）**；重送按 callback_url_snapshot 不随接口改址漂移
- 集成：补偿 worker 重送 PENDING→ACKED / 重送耗尽→DEAD_LETTER；四种转换场景端到端各 ≥1 例

### M4 容错与监控（10 人日）

| 任务 | 人日 |
|---|---|
| 熔断器（三态 + 闸门置于 @Retryable Invoker 调用前） | 3 |
| UNKNOWN 对账（上游查询协议 + 收敛策略 + 无查询能力人工兜底） | 3 |
| AOP 日志 + Micrometer/Prometheus + OTel 节点 span + 告警规则 | 4 |

**测试点**：
- 单测：熔断三态流转（CLOSED→OPEN→HALF_OPEN）；**OPEN 时短路、不触发 @Retryable**；对账收敛三分支（已成功→SUCCESS / 未到达→COMPENSATING / 无法查询→人工兜底）
- 集成：日志脱敏（手机号 / 密钥 / Header 敏感值）；traceId 贯穿出站与入站且与运行表 trace_id 关联；告警触发（成功率下降 / 死信堆积 / 补偿失败）

## 6. 关键依赖与风险提示

- **前置（开工前）**：三个重点设计项定稿（对应技术方案 §7 结论第 4 条）。
- **峰值对冲**：M2 的链引擎 + 映射引擎约占 10 人日，是唯一需要「先设计后编码」的部分——M0 契约评审不通过不得进入 M2。
- **并行约束**：多鉴权从 M0 后即可并行，但云厂商签名 / 回调验签需真实密钥，联调排在 M3 后。
- **新增安全测试点**：condition 表达式注入（动态映射引擎引入的新攻击面，demo 无表达式引擎故此前未暴露），已在 M2 单测与安全专项中列明。
