## 阶段一 · 界面上的「协议参数」区：显隐 + 输入约束 —— 约 5 分钟

> **为什么测**：这一阶段验的是**页面本身**——该出现的出现、不该出现的消失、
> 明显非法的输入在保存时被明确拒绝（而不是"存下去、调用时才炸"）。

## 阶段二 · 出站报文取证（**本能力的主战场**，页面）—— 约 6 分钟

> **为什么测**：声明 / 根元素 / 命名空间只体现在**出站报文的字节**上。
> 页面上的"最权威取证点" = **接口管理 →「测试接口」触发一次真实出站** →
> **接口监控 →「调用日志」→ 该接口 OUT 行 →「明细」抽屉 → 请求体**。

> **这个上游到底是什么类型**（容易误解，先说清）：`…/2.5_day.atom` 是 **Atom 1.0 聚合 Feed**
> （`Content-Type: application/atom+xml`，带 **GeoRSS 扩展** `georss:point`/`georss:elev`）——
> 属「**XML 文档型只读 API**」，**不是 SOAP**（无 Envelope/Body）、**不是 WSDL 服务**、**不是 XML-RPC**；
> **只接受 GET**（POST → 403），内容**每 60 秒滚动更新**（`cache-control: max-age=60`）。
> ⇒ 所以它能验证「**XML 解码 + RESP 白名单**」与「**平台编出的 XML 长什么样**」，
> 但**不能验证上游是否真的消费了我们的 XML 请求体**（GET 不携带 body，见阶段三 §3.3）。
> 同一数据的其他序列化：`.geojson`（JSON）、`.csv`、`.quakeml`（**QuakeML 行业 XML 标准**）；`.kml` 不可用
> （注意它返回 **HTTP 200 但响应体是 `404 File Not Found`**——又一个"别用状态码判成功"的例子）。
>
> **离线/确定性备选**：用仓库内的真实响应快照（裁剪为 2 条 entry，2044 字节）做 WireMock 桩：
> `src/test/resources/b1-protocol-params/usgs-atom-2.5day-2entries.xml`
> （保留三个可测特征：**默认命名空间** Atom、**`georss:` 前缀扩展**、**纯属性元素** `<link rel=… href=…/>` 与 **CDATA**）。

## 5. 常见误判（**先看这张表再报缺陷**）

| 页面上的现象 | 是不是缺陷 | 说明 |
|---|---|---|
| encoding 选 GBK 后，报文里中文显示成 `&#x4e2d;` 而不是 GBK 字节 | ❌ **不是** | 有意语义：`encoding` **只改声明**，非 ASCII 走字符引用、字节恒 ASCII 安全（Woodstox 实测产不出原生 GBK 字节，已记 backlog） |
| 下拉里**没有** UTF-16 / UTF-32 选项 | ❌ 不是 | 显式排除（会产原生非 ASCII 字节，破坏上述前提） |
| 「XML 协议参数」区在 JSON 协议时**不显示** | ❌ 不是 | 有意：JSON 接口配 xml 段会被后端拒（`40001`），界面直接不给入口 |
| 根元素填 `ns:QueryRequest` 被拒 | ❌ 不是 | 前缀要用「命名空间前缀」单独填 |
| 留空的项在回读时**没被写进配置** | ❌ 不是 | 前端**只下发非空键**（想过默认值就留空，而不是填空串） |
| GET 接口的 OUT 请求体有值，但上游说没收到 body | ❌ 不是 | GET/DELETE 不携带请求体（既有行为）；`请求体` 只代表"编码产物" |
| 「测试接口」执行后，调用日志里**只有 OUT 一行** | ❌ 不是 | 调试端点有意不落 IN 条（避免污染成功率口径） |
| 改了协议参数，**别的接口**也变了 | ✅ **是缺陷** | 协议参数是**接口级**（先确认是否误改到了同一接口 / 复制时选错行） |
